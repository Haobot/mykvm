# Windows 拖拽真机验证清单

- 适用版本：v0.9.13 及之后（本清单随 `Doc/Rfc/分级优化方案.md` 1.5 项建立）
- 背景：`windows_drag.rs`、`windows_drag_overlay.rs`、`windows_drop_catcher.rs` 三个模块的作者注释自述"仅通过 cargo xwin 类型检查，从未在真机 Windows 上验证运行时行为"。凡改动这三个模块（含 1.2 项的 DC/DIB 复用重构），合并前必须执行本清单至少一轮全量项。
- 环境：
  - 控制端与被控端各一台 Windows 真机（同一局域网），已完成发现与配对；
  - 被控端为本清单的执行观察对象；两端均为 Windows 时需双向各跑一轮；
  - 打开后端日志（运行 `mykvm.exe` 的控制台输出），每个场景记录关键日志行以定位失败阶段。

## 场景 A：控制端 → 被控端（拖出）

被控端光标由控制端驱动，把文件从被控端拖到控制端屏幕。

| # | 步骤 | 预期 | 结果 |
| --- | --- | --- | --- |
| A1 | 在被控端用鼠标左键拖动 1 个文件，向属于自己的屏幕边缘缓慢拖出 | 越界前出现隐藏 OLE 落点窗口接管（`windows_drop_catcher` 控制端路径），源应用的拖拽不中断 | ☐ |
| A2 | 光标越过边界进入控制端屏幕 | 控制端出现拖拽浮层图标（`windows_drag_overlay` FOLLOW 模式）并跟随光标 | ☐ |
| A3 | 观察浮层进度条 | 传输期间进度条随剩余字节推进 | ☐ |
| A4 | 松开左键于控制端桌面 | 文件落在松开点所在位置；浮层在传输未完成时停靠任务栏上方（DOCKED），完成后消失 | ☐ |
| A5 | 检查落点文件 | 文件大小、内容与源文件一致（对比哈希） | ☐ |
| A6 | 拖动到控制端某个接受拖放的应用窗口（如资源管理器子目录、记事本附件区） | 该应用正常接受拖放（`DoDragDrop` 真实会话生效） | ☐ |

## 场景 B：被控端 ← 控制端（拖回 / 对端落地）

被控端运行真实 `DoDragDrop` + `IDataObject`/`IStream` 路径（`windows_drag.rs`）。

| # | 步骤 | 预期 | 结果 |
| --- | --- | --- | --- |
| B1 | 在控制端拖动 1 个文件跨越边界到被控端屏幕 | 被控端渲染原生拖拽图像（系统拖影，非自绘） | ☐ |
| B2 | 继续拖动 | 浮层跟随且进度条推进（`IStream` 边传边读） | ☐ |
| B3 | 松开在被控端桌面 | `signal_drop` 结束会话，文件落地且内容一致 | ☐ |
| B4 | 松开在被控端接受拖放的应用（微信聊天框、邮件客户端等） | 应用正常收到拖放 | ☐ |
| B5 | 被控端用注入输入拖动文件拖回控制端（`handoff_to_controller` 路径） | 光标停在边界、落点窗口停靠光标下并补一次命中测试，文件传回控制端光标释放处 | ☐ |

## 场景 C：取消路径

| # | 步骤 | 预期 | 结果 |
| --- | --- | --- | --- |
| C1 | 拖出过程中（浮层 FOLLOW 时）按 Esc | 本地源应用拖拽被取消；无文件传输残留；无临时文件遗留 | ☐ |
| C2 | 拖出到对端后、松开前按 Esc | 会话以 `cancel_session`/`DRAGDROP_S_CANCEL` 结束；两端均无残留文件与浮层 | ☐ |
| C3 | 拖出过程中直接把光标拖回本屏深处松开 | 视为本地放置，不触发跨机传输 | ☐ |
| C4 | 传输进行中直接断开两端网络（禁用网卡） | 传输中止、浮层消失、无崩溃，重连后可再次正常拖拽 | ☐ |

## 场景 D：边界条件

| # | 步骤 | 预期 | 结果 |
| --- | --- | --- | --- |
| D1 | 一次拖动 64 个小文件 | 全部传输并落地，数量与命名一致 | ☐ |
| D2 | 一次拖动单个 ≥ 2GiB 的文件 | 全部字节落地，哈希一致（重点覆盖 `nFileSizeHigh`/`nFileSizeLow` 高位与 `IStream` 溢出边界） | ☐ |
| D3 | 一次拖动混合集合：文件夹（含嵌套）+ 多个文件 + 0 字节文件 | 目录结构还原、0 字节文件正确创建 | ☐ |
| D4 | 拖动到目标位置存在同名文件 | 出现系统标准冲突确认框（复制/替换/跳过），选择后行为正确 | ☐ |
| D5 | 拖动进行中用另一只手段（触控/第二鼠标）干扰光标 | 不崩溃；会话仍能正常结束或取消 | ☐ |

## 场景 E：浮层专项（1.2 项 DC/DIB 复用回归）

> 本节在 1.2 项（`windows_drag_overlay.rs` 复用 DC 与 DIB、仅每帧 `UpdateLayeredWindow`）落地后为必测项；用于确认无 GDI 句柄泄漏与渲染错乱。

| # | 步骤 | 预期 | 结果 |
| --- | --- | --- | --- |
| E1 | 长拖：单个大文件（>1GiB）持续传输 ≥ 60s，任务管理器观察 GDI 句柄数 | GDI 句柄数稳定不增长 | ☐ |
| E2 | 浮层渲染 | 图标边缘无黑边/毛边（per-pixel alpha 正常），进度条无残影 | ☐ |
| E3 | 连续 10 次短拖（每次 < 2s） | 每次浮层正常出现/消失，无残留窗口（Alt+Tab 与屏幕检查） | ☐ |
| E4 | 拖动跨多显示器（若有） | 浮层在显示器间切换位置正确，不出现在错误屏幕 | ☐ |
