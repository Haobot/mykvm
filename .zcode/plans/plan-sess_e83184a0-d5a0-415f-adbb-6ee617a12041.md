# 按网络记忆设备配置 + 离线设备自动清理

## Context

当前痛点：设备一旦配对就永久留在 `devices[]` 里，只会打「离线」徽标；换到另一个 WiFi 后，旧网络的设备全部挂着离线不走，而新网络下曾经配对过的设备配置也找不回来。用户要求：

1. 设备离线后主动尝试 **5 次**，仍无效 → **静默删除**（日志记录，不弹确认）；
2. **按网络分组记忆设备列表**：以「接口名+子网指纹」标识当前网络（如 `en0=192.168.1.0/24`），切换网络时把当前远程设备存入旧网络的档案、载入新网络档案里留下的配置；
3. **手动设备（`source=="manual"`）全局保留**：不参与分组、永不自动删除；
4. 本地设备（`role=="local"`）自然始终保留。

探索结论（现状）：
- 无 SSID/网络变化监听；唯一网络感知是发现循环里每 10s 的 `collect_local_ip_addresses()` diff（`src-tauri/src/lib.rs:1351-1372`），且 `if-addrs` 的 `Ifv4Addr` 自带 `netmask`，可直接算子网。
- peer 表有 TTL 淘汰（`PEER_TTL_MS=90s`，`lib.rs:13952`），但 **devices 表无任何自动删除**；设备离线只由 `apply_peer_presence` 翻 `online` 位（`lib.rs:11994`）。
- 设备列表唯一写路径是前端 `save_layout`（`lib.rs:2038`）全量覆盖 + `merge_runtime_owned_layout_fields`（`lib.rs:4285`）合并——**后端若直接改 devices，前端一次陈旧保存就能把删除/换网结果冲掉**，这是本方案必须解决的多写者竞态。
- 删除设备的前端参照实现：`handleRemoveDevice`（`src/App.tsx:2427`）——含 `activeDeviceId`/`selectedScreenId` 回退逻辑，后端删除时要复刻。

## 方案

### 分支

按仓库约定先建分支 `feat/network-profile-offline-cleanup` 开发，验收后再合 main。

### 1. 数据模型（`src-tauri/src/lib.rs` 的 `LayoutState`）

新增三个 serde default 字段（旧 layout.json 兼容）：

```rust
#[serde(default)] layout_revision: u64,          // 后端设备列表变更代数（多写者竞态防护）
#[serde(default)] active_network_key: String,    // 当前 devices[] 属于哪个网络档案
#[serde(default)] network_profiles: HashMap<String, NetworkProfile>,
```

```rust
struct NetworkProfile { devices: Vec<Device>, #[serde(default)] saved_at_ms: u64 }  // camelCase
```

贯通点：
- `normalize_saved_layout`（`lib.rs:8185` 构造处）：透传三个新字段；
- `normalized_transient_clone`（`lib.rs:7524`）：落盘时把 **profiles 内设备** 的 `online/input_ready/upgrading` 也清零（与顶层 devices 同规则）；
- TS 镜像 `src/types.ts` `LayoutState` + `src/defaultLayout.ts` 补默认值（前端只是整对象透传，加类型保证 round-trip 不丢）。

### 2. 网络指纹与换网（新模块 `src-tauri/src/network_profile.rs`）

纯函数 + 自带 `#[cfg(test)]`，lib.rs 根模块私有项对子模块可见，无需改可见性：

- `network_fingerprint(candidates) -> String`：复用 `collect_local_ip_candidates` 的过滤规则（`is_excluded_interface_name`、`usable_discovery_ipv4`），补取 `netmask`，每接口产出 `iface=网络地址/前缀`（如 `en0=192.168.1.0/24`），排序去重拼接。**空指纹（无可用地址）视为未知网络，不触发任何操作**。
- `swap_network_profile(layout, new_key) -> bool`：
  1. 把 `devices[]` 中非 local、非 manual 的设备存入 `network_profiles[active_key]`（`active_key` 为空=首次采用，只记 key 不暂存）；
  2. `devices[] = local + manual + network_profiles[new_key].devices`（按 id 去重）；
  3. 修正 `active_device_id`/`selected_screen_id`（复刻 `handleRemoveDevice` 的回退：失效则落到首个设备/其首个屏幕）；
  4. `active_network_key = new_key`；`layout_revision += 1`。

**触发点**：发现循环 10s 身份刷新块（`lib.rs:1351-1372`）内，紧挨现有地址 diff 逻辑：
- 指纹连续 **2 个周期（≈20s）稳定且非空** 才换网——避免 WiFi 切换瞬态（接口 down/up、链路本地地址）在两个档案间抖动；
- 换网后清空离线重试计数、`write_layout_to_disk` 落盘、`log::info!("network profile swapped ...")`；
- 前端经既有 2s 轮询 `loadAppState` 自动拿到新列表（无需新事件）。

### 3. 离线 5 次重试后静默删除（同在发现循环）

状态：`offline_misses: HashMap<String, u32>` + `last_offline_probe: Instant`（均运行时，不落盘）。

每 `OFFLINE_PROBE_INTERVAL_MS = 10_000` 一轮，对满足全部条件的设备：
- `role != "local"`、`source != "manual"`、`!online`、`!upgrading`（升级 120s 宽限期内不动）；
- **本地地址集合非空**（网络没起来绝不计数——防止开机/WiFi 未连时把整表误删）；

执行：
1. 向 `device.host:transport_port` 发既有 unicast probe（复用 `send_discovery_packet(..., "probe", ...)` 非阻塞发送，回复走既有 recv 路径合并，设备活着会自己 announce 回来）；
2. `misses[id] += 1`；设备回到 online 时移除计数；
3. `misses[id] >= OFFLINE_PROBE_MAX_MISSES (=5)` → 从 `devices[]` 移除、修 active/selected 回退、`layout_revision += 1`、落盘、`log::info!("offline device auto-removed ...")`。

失败注入防护（与 `prune_stale_peer_entries` 同哲学）：计数只活在发现循环内——循环停摆=不计数=不删；`Instant` 计时免疫时钟跳变。

### 4. 多写者竞态防护（关键）

`merge_runtime_owned_layout_fields`（`lib.rs:4285`）改为：
- **比较** `incoming.layout_revision` 与 `current.layout_revision`（前端原样回传 loadAppState 拿到的值）；
- 相等 → 现状语义（incoming devices 胜，用户增删改有效）；
- **不等（陈旧快照）** → `incoming.devices = current.devices.clone()`，丢弃陈旧设备列表但保留其它前端字段，并 `log::warn!`；最后统一 `incoming.layout_revision = current.layout_revision`；
- `active_network_key`/`network_profiles` 一律后端所有，始终取 `current`（同 `cluster_id` 处理方式）。

这同时挡住两条竞态：陈旧保存复活已删设备、换网后旧列表覆盖新档案。`runtime_relevant_layout_changed` 无需改（设备增删本就不触发 runtime 重启）。

### 5. 前端（`src/`）

- `types.ts` / `defaultLayout.ts`：补 `layoutRevision`、`activeNetworkKey`、`networkProfiles` 三字段（纯类型+默认值，round-trip 用）；
- 无 UI 改动：设备列表、离线徽标、`handleRemoveDevice` 全部照旧工作；换网/自动删由 2s 轮询自然刷新。

### 6. 明确的非目标

- `pairedControllers[]` 不按网络分组（证书鉴权，host 可后补）；
- 不做 SSID 获取、不做原生网络事件订阅（沿用 10s 轮询，RFC「网络抗干扰」P1 另行处理）；
- 不做档案数量上限（每个网络一个几十字节的档案，可忽略）。

## 真机验证

1. 构建安装（`sh scripts/install-mac-app.sh`），日志应有 `discovery started`、`discovery peer updated`（AGENTS.md 清单）。
2. **离线删除**：对端关机 → 日志出现 probe 尝试，约 50s（5×10s，叠加 peer 90s TTL 后总计约 2.5 分钟）出现 `offline device auto-removed`，UI 列表同步消失；期间对端开机则计数归零、设备恢复。
3. **换网记忆**：网络 A 配对设备 → 切到网络 B（日志 `network profile swapped`，列表只剩 local+manual）→ 在 B 配对新设备 → 切回 A → A 的设备原样回来（离线状态正常），再切到 B → B 的设备回来。
4. **防护**：换网瞬间快速改一下设备设置并保存 → 不应把旧网络列表写回去（日志有 stale save warn）。
5. Windows 端（GT37）全平台编译先行：`cargo check --target x86_64-pc-windows-msvc`（或至少 macOS/Linux 双 check），确认新模块无平台条件编译问题。
