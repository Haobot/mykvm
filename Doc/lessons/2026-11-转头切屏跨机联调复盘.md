## 3. 教训

1. **跨机协议永远不要假设对方和你共享坐标系或 id。** 板面坐标、设备 id（AGENTS.md #6 的同族坑）
   都是各自本地化的。正确姿势：线上只传「目标对象内局部坐标 + 可规范化 id」，接收端用自己的
   几何/命名解析；id 匹配要带前缀剥离（`rsplit "-local-display-"` 容忍主机名连字符）。
2. **功能分支在进入跨机联调前必须全平台编译+测试过一遍。** 本次三层编译/测试问题（cfg 门控、
   Linux 桩参数、win32 测试盲写期望值）全部堆在联调夜暴露，每轮 CI 13 分钟烧掉整晚节奏；而且
   main 上 CI 自 P0-P4 合并后红了一天没人看——合并前看 CI 应是硬门槛。
3. **不可复现的问题先补观测再修。** 「按钮无法按下」在浏览器可复现正常、应用内零线索，四层
   面包屑（点击→persist→save_layout begin→写盘）一轮就把断点钉在"点击从未到达"。状态改变
   链路默认埋点，成本极低。
4. **同名 UI 控件是认知地雷。** 调试按钮与设置开关同叫「显示光环」，用户、开发者、日志三方
   都被误导。遗留调试 UI 要么删、要么命名区隔（本次直接删了 224 行）。
5. **多层根因必须逐环实证，"修好了"的复测就是下一层的探针。** 四层根因没有任何单点调查能一次
   看全；每一轮复测的"部分好转"（有边框了/没光标）都是精确的层间分界证据。
6. **观测工具本身会伪证，关键结论要双源。** 本次踩过：沙盒令牌虚拟化文件写入与命名事件（安装
   失败是假的）、离屏 WKWebView 截图空白（应用死了是假的）、`strings` 查压缩嵌入资产（版本旧
   了是假的）、日志快速轮转（没发过包是假的）、bash 管道采样器匹配 bug（窗口没了是假的）。
   单一工具的阴性结论下结论前，换一个正交手段复核。
7. **诊断信息要能落地成产品修复。** Win 端取证发现的 NSIS 钩子弱点（taskkill 失败被忽略）、
   更新器端点指向上游仓库（XxMinor→Haobot，main 同病）、实例退出零日志，都是排障过程的副产
   品，顺手修掉才不浪费整晚的取证成本。
