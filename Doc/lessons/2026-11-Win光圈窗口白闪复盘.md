# 2026-11 Windows 光圈窗口白闪复盘

> 范围：Mac 控制端点选 GT37（Windows 被控端）磁贴时，被控端物理屏应只闪蓝色光圈，
> 实际先后出现「全白一闪 → 放大的白色边框遮罩 → 由小到大缩放的白框」三种白色伪影。
> 涉及提交：见本文件末尾（feat(input) 解码失败可观测性、fix(布局) 光圈白闪、fix(build) 资产脚本）。
> 结论先行：白闪不是一个原因，是**四层叠加**，逐层修才能干净——WebView2 首帧白底、
> Win11 DWM 给无边框窗口照画的系统白边框、Win11 开窗缩放动画把白底窗口放大上屏、
> 以及「页面加载完成 ≠ 合成器已交出首帧」的时序差。最终方案：隐藏创建 + 延迟显示 +
> 两个 DWM 属性，白帧物理上无法上屏。

## 1. 现象（随修复逐轮演进）

| 轮次 | 用户看到 | 当时机内的修复 |
| --- | --- | --- |
| 1 | 屏幕先**全白**再闪蓝色边框 | 无（首次带上 FlashScreen 的构建） |
| 2 | 白色依旧，描述为**放大的白色边框透明遮罩** | webview 透明默认背景（`background_color` RGBA 0） |
| 3 | **由小到大缩放的白框** | 再加 `DWMWA_BORDER_COLOR=DWMWA_COLOR_NONE` |
| 4 | ✅ 只剩蓝色光圈，与 Mac 一致 | 再加 `DWMWA_TRANSITIONS_FORCEDISABLED` + 隐藏创建、`Finished` 后 60ms 才 `show()` |

指示页 `public/screen-indicator.html` 是纯 CSS（透明背景 + 10px 蓝框），**CSS 里没有任何白色**；
两端共用同一页面，macOS 从未出现白色伪影——差异全部在窗口层。

## 2. 根因：四层叠加

1. **WebView2 首帧白底**：页面 CSS 合成前，WebView2 用默认白色背景绘制。设
   `background_color(透明)` 可减轻，但只覆盖 webview 层。
2. **Win11 DWM 系统边框**：无边框（undecorated）窗口在 Win11 仍画 ~1px DWM 边框，
   浅色主题下是**白色**，贴着全屏窗口外缘——看起来是比蓝圈（内缩 8px）更大的白框。
   macOS 无边框窗口无系统边框。修法：`DwmSetWindowAttribute(DWMWA_BORDER_COLOR, DWMWA_COLOR_NONE)`。
3. **Win11 开窗缩放动画**：`show()` 触发 DWM 把窗口从小放大（约 150ms）。窗口在
   WebView2 交出首帧前被显示时，被动画放大的是**不透明白底**——即「由小到大的白框」。
   修法：`DwmSetWindowAttribute(DWMWA_TRANSITIONS_FORCEDISABLED, 1)`。
   （macOS 该窗口本来无开窗动画，禁掉反而是视觉对齐。）
4. **`PageLoadEvent::Finished` ≠ 首帧已呈现**：DOM 就绪事件触发时合成器可能还欠一帧；
   立刻 `show()` 仍可能露出白底。修法：`Finished` 后再等 ~2 个 vsync（60ms）再显示。

**最终形态**（`run_screen_flash_window`，lib.rs）：
`visible(false)` 创建 → `on_page_load(Finished)` → 起 60ms 定时线程 → `show()`；
外加 `clear_screen_indicator_border` 打两个 DWM 属性、`background_color` 全透明。
窗口在不可见状态下无论多白都上不了屏——这是唯一可靠的保证。

## 3. 连带发现：新观测功能照亮了自家预热流量

同日上线的「输入包解码失败计数 + 限流 warn」（三 schema 全败才计数）装到 GT37 后
**每 ~4 秒告警一次 `(0 bytes) from <Mac>:47834`**——`warm_quic_peer`（lib.rs）发空数据报
做 QUIC 路径预热，以前被静默丢弃、无迹可查，被新观测当成了版本混跑。修复：0 字节载荷
在计数前直接返回（任何 schema 都不可能是 0 字节 ⇒ 必是自家预热）。
经验：**给静默路径加观测，第一波告警大概率照出的是自家合法流量的盲区**，上线前先审一遍
「谁还会走这条路径」。

## 4. Windows 本地构建环境经验（GT37 从零搭起）

- 工具链：winget 装 VS Build Tools 2022（VCTools 工作负载）+ rustup `stable-x86_64-pc-windows-msvc`；
  WebView2 运行时 Win11 自带。
- **裸 `npm run tauri -- build` 会卡死**：本地无 `TAURI_SIGNING_PRIVATE_KEY`，必须与 CI 同参
  `--ci -b nsis --config '{"bundle":{"createUpdaterArtifacts":false}}'`。
- **tauri 首次打包要下载 NSIS 工具链（GitHub）**：VPN 走系统代理（WinINET）时 tauri 的
  下载器不读系统代理，需 `export http_proxy=… https_proxy=…`（本机 127.0.0.1:5782）。
- **`build-tauri-assets.mjs` 的 npm 双重路径坑**：`cmd /c npm` 在 `npm run` 生命周期里会
  解析到 npm 自带 bin 目录里的内层 `npm.cmd`，其前缀探测把 `npm-cli.js` 拼成双重路径
  （`…\npm\bin\node_modules\npm\bin\npm-cli.js`）→ MODULE_NOT_FOUND。修法：直接
  `node $npm_execpath`（`npm run` 环境必设），cmd shim 仅作兜底。
- **NSIS patcher 会回写 target exe**：打包后 `target/release/mykvm.exe` 与装机 exe 哈希不同
  （尺寸相同）——patch 在 makensis 取文件之后落盘，属正常，不要据此怀疑装错版本。
- Windows 全量 `cargo test --lib` 为 415 条（AGENTS.md 的 218 是 macOS 侧数字）。

## 5. 验证

- `cargo test --lib` 415/415（Windows）、`npm test` 45/45、rustfmt 仅改动文件。
- 装机日志：`discovery started` 正常、0 字节告警从每 4 秒一条降为零。
- 用户三轮目测后确认：GT37 光圈只剩蓝色脉冲，与 Mac 端一致。
