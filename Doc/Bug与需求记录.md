## BUG-001 被控端未接外接鼠标时，该机光标不显示

- 类型：Bug　严重度：高　状态：待排查　记录日期：2026-11-17
- 发现方式：真机使用（用户报告）

**现象**

- 被控（接收端）电脑**没有外接任何鼠标**时，那台电脑屏幕上的光标不显示。
- 即鼠标已从本机穿越过去、焦点也在对端，但对端屏幕上看不到指针位置。

**复现步骤（待补全）**

1. 被控端不接任何鼠标（仅用内置触控板或无指针设备）。
2. 本机端把鼠标推入被控端屏幕范围。
3. 观察被控端屏幕：光标不显示。

**期望**：无论被控端是否接有物理鼠标，被控期间对端屏幕上都应显示受控光标。

**影响**：无法确认指针位置，被控端基本不可用。

**初步线索（未验证，仅供排查起点）**

- 需先确认这是「注入端未发送移动事件」还是「对端未渲染光标」：查 `src-tauri/src/input.rs` 的注入路径与日志中是否有本地注入的 move 事件。
- 与 BUG-002 同属「本地光标与注入解耦」机制（`CGAssociateMouseAndMouseCursorPosition`，见 BUG-002 的 `5c17811`），排查时一并确认该机制在**本机无物理指针设备**时是否导致光标不绘制。
- 待确认 macOS 侧是否存在「无物理指针设备时隐藏/不绘制本地光标」的系统行为，如属系统行为需考虑由应用自行绘制光标。

**真机取证方案（2026-11-18 补充，暂不动代码）**

- 代码现状：被控端注入为「warp + posted CGEvent」绝对定位（`inject_mouse_move`），并依赖 `NSCursor setHiddenUntilMouseMoves(false)` 恢复可见；全仓无「无物理指针」相关处理。可见性押在 WindowServer 会不会为纯注入事件画光标上。
- 取证步骤（被控端不接鼠标重演）：
  1. 两端日志按时间戳对齐：控制端确认 `send_remote_mouse_move` 持续发出（排除注入端未发送）；
  2. 被控端确认 QUIC 收包并走到 `inject_input_command`（如日志不足先补注入路径日志再复演）；
  3. 被控端接回鼠标观察光标是否「动而不见/根本没动」，区分「warp 未生效」与「NSCursor 隐藏未恢复」；
  4. 若确认系统行为，评估被控端软光标 overlay 方案另立条目。

**关联**：BUG-002（光标解耦机制相关）

## BUG-002 操作被控端时，本机一侧光标同时移动（双光标同时动）

- 类型：Bug　严重度：高　状态：已定位（待复验）　记录日期：2026-11-17
- 发现方式：真机使用（用户报告）

**现象**

- 本机端操作被控端时，**本机自己的光标也在移动**，表现为两端光标同时动（双光标）。
- 期望是「焦点交给被控端后，本机光标停住/隐藏」。

**复现步骤（待补全）**

1. 鼠标穿越到被控端屏幕。
2. 在被控端范围内移动鼠标。
3. 观察本机端屏幕：本机光标同样在移动。

**期望**：焦点在被控端期间，本机光标保持不动或隐藏，避免视觉上出现两个光标。

**影响**：视觉混乱，容易被误认为在操作本机；可能与 BUG-001 同源（光标可见性/位置回写策略）。

**初步线索（未验证，仅供排查起点）**

- 关注捕获端（发送输入的一方）在进入「转发模式」后是否仍把物理移动应用到本地光标（`src-tauri/src/input.rs` 捕获/隐藏路径）。
- 关注是否存在对端回传的坐标被写回本机光标。

**已有相关修复（需确认复现所用构建）**

- 主分支上已有针对性提交 `5c17811 fix(input): 修复远程控制中本地光标随鼠标移动的双光标问题`（2026-11-04，已并入 `origin/main`）。其说明：「macOS 在 app 后台会悄悄恢复 `CGAssociateMouseAndMouseCursorPosition` 关联，本地光标重新跟手而注入继续，表现为 Mac/Win 两个光标同时移动」，修复点为 `input.rs` 中 `repin_macos_cursor_if_drifted` 无条件重断言解耦、`decouple_pending` 全路径清理 + 1s 超时兜底、Windows 侧滞留自修复。
- 本次复现的构建是否包含该提交**未确认**：
  - 若复现于**不含该提交**的分支（如当时的 `feat/network-resilience-p0`）→ 属旧问题，需在含该提交的构建上复验。
  - 若复现于**含该提交**的构建 → 该修复未覆盖全部路径（例如「无外接鼠标」或特定后台/锁屏状态），需继续定位。

**分支考证结论（2026-11-18 补充）**

- git merge-base 验证：`feat/network-resilience-p0`（复现所用分支）**不含** `5c17811`，其上的 input.rs 仍是修复前旧逻辑（无条件重断言缺失、pending 无超时、无退出路径清理、无 stale-active 自愈）→ 本次复现**属旧问题**，与既有修复不矛盾。
- 验收构建 `fix/layout-crossing-overlap` 基于 `origin/main`（含 `5c17811` 与全部既有工作），装上后直接复验本条目。

**关联**：BUG-001（同为光标可见性/位置表现问题，建议合并排查）

## BUG-003 布局中「本机外扩屏」与「被控屏」并排时，可能无法左右互相穿越

- 类型：Bug　严重度：高　状态：待验收　记录日期：2026-11-17
- 发现方式：真机使用（用户报告）

**现象**

- 在布局界面把「被控电脑的屏幕」与「当前主机的扩展屏」**并排摆放**后，两者之间**有可能无法互相左右穿越**。
- 用户描述为「有可能」，怀疑与摆放时的相对位置（边缘是否对齐、是否吸附到位）有关。

**复现步骤（待补全）**

1. 布局中放置本机主屏 + 本机扩展屏 + 被控设备屏幕。
2. 将被控屏幕与本机扩展屏左右并排。
3. 尝试在两者之间来回穿越鼠标。

**期望**：只要两块屏幕在布局中并排贴边，就应能双向自由穿越。

**影响**：多屏场景下穿越失效，而发现/连接状态一切正常，用户无从判断原因。

**初步线索（未验证，仅供排查起点）**

- 疑似与既有文档同源：[显示器重叠自动分离方案](Rfc/显示器重叠自动分离方案.md) 记录了穿越判定（`touching_edge`）要求两屏**边缘对齐**且**投影重叠**；因此「并排但未精确对齐」与「重叠」都可能判不出贴边。本条目补充的场景是**本机扩展屏 ↔ 被控屏**这一对，需确认是否同一根因、是否被既有方案覆盖。
- 排查时记录布局坐标、两侧屏幕矩形与日志中的 target 生成结果。

**关联**：[Doc/Rfc/显示器重叠自动分离方案.md](Rfc/显示器重叠自动分离方案.md)

**定位结论与修复（2026-11-18，`fad8272`，待验收）**

- 代码考古：重叠自动分离方案**已实施**（`e517e16`，前后端均有最小位移分离），本条目是它的漏网场景——分离/吸附只保证**相切**，而穿越判定还要求**投影重叠**。
- 根因一：`touching_edge` 的 `ranges_overlap` 原要求投影重叠**严格 >80px**（`input.rs`）。两屏窄投影并排（如错位 1~80px）或角对角相切（投影为 0）时判不出贴边，`build_input_targets` 不生成 target → 无法穿越，与摆放结果是否来自吸附无关。
- 根因二：拖拽吸附两轴独立（容差 80px），可以产出「x 边恰好相切 + 垂直方向恰好相接（投影 0）」的切角布局——视觉相邻、永远不可穿越；分离算法只在真正重叠时触发，不会纠正这种状态。
- 修复：① `ranges_overlap` 放宽为投影 >0（边缘对齐 ±80 仍是主防线）；② `separate_layout_screen_overlaps` 新增切角对齐 pass（非本机屏近相切 ±8px 且投影为 0 时沿中心方向对齐），presence tick / 启动加载统一生效，拖出的切角布局约 1s 内被拉直。
- 验收要点：被控屏拖到与扩展屏「角对角/小错位」贴边 → 约 1~2s 内自动对齐、可双向穿越。

**修复回归：切角对齐引发每秒振荡（2026-11-18，`c20c9ce`）**

- 真机验收 BUG-004 时发现：`fad8272` 的对齐 pass 用「单轴边缘共线 ±8px 且投影为 0」判定切角接触——真机布局中被控屏与 local3 **顶边共线但水平相距 167px**（完全不相邻）也被误判，被整屏拉 2460px 压到 local2 上 → 分离级联推回 → 与 local2 底边共线 → 下一 tick 再被拉走，presence tick 每秒循环一次。表现为布局反复重叠、手动调整约 1s 后被自动跳回。
- 修正（`align_tangent_position`）：① 触发改为**两轴 range gap 同时 ≤8px**（真·角对角接触），单轴共线但远离不再触发；② 动作从整屏对齐改为**沿中心更近轴推入 40px**，共享边恰好获得可穿越投影带；③ 候选位置与任何屏重叠则放弃——分离 pass 永不与对齐打架，跨 tick 收敛。
- 回归用例：真机 4 屏布局连续两个 tick 结果一致（`layout_normalization_leaves_a_real_resolution_changed_layout_stable`）、共线远离不触发用例。

**验收反馈补充：从非进入边回不到本机（2026-11-18，随 `fix(输入)` 提交修复）**

- 真机摆放被控屏**左右贴外扩屏（进入边）、底部贴主屏**后，从外扩屏进入被控屏再向下推光标回不到主屏。几何层 target 生成正常（相切 + 投影完整），卡点在回穿引擎：`update_active_remote_screen` 只认**进入时的那条边**（原注释假设「只有进入屏贴着本机」——多本机屏布局下该假设不成立），其余边一律钳住。
- 修正：越出远端屏且无同设备邻屏时，判定实际越出的边，在 targets 中找配对该边的 target（screen_id + 对侧 edge）；找到则把生效 target 切换为该配对并返回，落点在那块本机屏的贴边上；该边不贴任何本机屏时维持钳住。进入边经典返回路径与防回弹检查不变。
- 回归用例：`cursor_returns_to_local_through_a_second_bordered_edge`（双贴边布局从底边退出落到下方主屏）。

## BUG-004 切换屏幕分辨率后，「屏幕排布」界面中屏幕可能重叠导致错误

- 类型：Bug　严重度：高　状态：待验收　记录日期：2026-11-18
- 发现方式：真机使用（用户报告）

**现象**

- 切换某块屏幕的分辨率后，回到「屏幕排布」界面观察/调整时，屏幕矩形**有可能互相重叠**，进而导致错误（结合 BUG-003/RFC 已知：重叠会使穿越失效）。
- 用户原话为「在屏幕排布界面里调整分辨率」，具体指系统设置里改分辨率还是指界面内操作，复现时需向用户澄清；前端代码中未检索到分辨率调整控件，暂按「系统层切换分辨率后布局未消解重叠」记录。

**复现步骤（待补全）**

1. 布局中两块屏幕已正常并排、可穿越。
2. 在系统设置中切换其中一块屏幕的分辨率（或按用户澄清后的具体操作执行）。
3. 观察「屏幕排布」界面：屏幕矩形可能重叠，穿越随之失效。

**期望**：分辨率切换引起屏幕尺寸变化后，布局应自动重新消解重叠（保持相切贴边），穿越不受影响。

**影响**：与 BUG-003 同族——重叠后穿越静默失效，发现/连接状态正常，用户无从判断原因；且由「分辨率切换」这一常见操作触发，命中面更广。

**初步线索（未验证，仅供排查起点）**

- 分辨率切换会改变屏幕矩形尺寸，布局中保存的相对位置仍按旧尺寸摆放，尺寸变化后相邻屏可能不再相切而互相重叠；需确认前端 `src/layout.ts` 的重叠消解（`snapOverlappingScreenPosition` 等）是否只在拖拽/键盘调整后执行，分辨率变化路径绕过了它。
- Rust 侧有 display configuration change 处理（`src-tauri/src/lib.rs` 约 4869 行起 `local displays changed` 日志），会刷新 announce 与 input targets；需确认该路径是否触发前端布局重新消解重叠，还是只透传新尺寸。
- 若重叠成立，`build_input_targets`（`src-tauri/src/input.rs`）会跳过重叠屏 → 无法穿越，与 BUG-003 表象同源；需确认 [显示器重叠自动分离方案](Rfc/显示器重叠自动分离方案.md)（拖拽/首摆两层防线）是否覆盖「分辨率变化」这一触发路径。
- 复现时记录：改哪块屏的分辨率、改前/改后布局坐标与屏幕矩形、是否触发自动分离、`mykvm.log` 中 `local displays changed` 前后的 target 生成结果。

**关联**：BUG-003（同为重叠/贴边穿越失效）；[Doc/Rfc/显示器重叠自动分离方案.md](Rfc/显示器重叠自动分离方案.md)

**定位结论与修复（2026-11-18，`fad8272`，待验收）**

- 根因：macOS 显示器 watcher（1.5s 指纹轮询 × 2 拍防抖）→ `refresh_local_screens` → `apply_detected_local_screens` 保留画布 x/y、替换新尺寸后**不经过任何重叠消解**直接写盘；前端无显示器事件、靠 2s 轮询原样展示。此后虽有 discovery tick 的 presence pass 兜底分离，但存在数秒重叠窗口，且重叠布局已落盘。
- 修复：`refresh_local_screens` 在持久化前调用 `separate_layout_screen_overlaps`（只推非本机屏），内存与 `layout.json` 同步干净；该函数现含切角对齐 pass，分辨率变化后的自动分离结果直接满足穿越判定。日志新增 `separated peer screens overlapping resized local screens`。
- 已知边界（未在本轮处理）：**Windows 无显示器变化 watcher**——Windows 本机热切换分辨率完全不感知（仅远端屏变化经 announce 链路生效），需另立条目。
- 验收要点：系统设置切换本机屏分辨率 → 约 3s 内布局自动分离无重叠（前端 2s 轮询内反映），穿越不失效；日志成对出现 `local displays changed` 与分离日志。

## BUG-005 布局点选磁贴的光圈在 Mac 外接屏上不显示（仅主屏能闪）

- 类型：Bug　严重度：中　状态：已关闭　记录日期：2026-11-18
- 发现方式：真机使用（用户报告，属「点选磁贴闪光圈」需求上线后的缺陷）

**现象**

- 在「显示器布局」画布点选本机磁贴：主屏（内建 Retina 屏）能正常闪出蓝色光圈；点选**外接屏**磁贴时对应物理显示器上没有任何反应（连续点击多次也不出现）。

**定位结论（2026-11-18）**

- 日志取证：`screen indicator` 回读显示窗口的 Cocoa frame 与 level 全部正确落在目标外接屏（如 `(1512,-458) [2560x1440] level=1000`）——NSWindow 定位/层级链路没有问题。
- 根因：光圈内容是透明 WKWebView 页面。WebView 窗口由 tao builder 以**错误的初坐标**创建（tao 在 Retina 主屏下用物理像素高翻转逻辑 y），随后才 `setFrame` 跨显示器挪到外接屏；WKWebView 在这种"初建于错误位置、之后跨显示器移动"的场景下**不重绘**（Tauri/WebKit 已知问题），透明窗 + 未渲染内容 = 完全不可见。主屏初始位置碰巧近似正确，所以能画。

**修复（`494b2e8`，分支 `fix/native-screen-flash`）**

- 弃用 WebView 光圈窗，双端改走 halo 浮层同款原生窗口路径（同构浮层在外接屏上实测可见）：
  - macOS：无边框点击穿透 NSWindow + CAShapeLayer 圆角描边，Core Animation 驱动 0.45s×3 交替脉冲，1.4s 后 orderOut+release；NSScreen 点级几何匹配沿用，匹配失败兜底按主屏点高翻转（不再退回 tao 坐标）。
  - Windows：`WS_EX_LAYERED` 分层窗 + GDI DIB 像素脉冲（复用 halo win32 的渲染思路），用 `GetDpiForMonitor` 按逻辑矩形选屏，自带消息循环线程 1.4s 自毁；`windows-sys` 补 `Win32_UI_HiDpi` feature。
- 删除 `public/screen-indicator.html` 与 lib.rs 的 WebView 光圈路径；新实现集中在 `src-tauri/src/screen_flash.rs`，本机画布点击与被控端 FlashScreen 事件共用同一入口。
- 视觉规格对齐原 html：内缩 8px、10px 蓝色描边（rgba(56,150,255,.92)）、圆角 18、三拍脉冲。

**验收记录（2026-11-19，已关闭）**

- 修复最终形态：光圈实现抽成 `flash-core` crate；macOS 27 上 Tauri 进程内创建的跨显示器 NSWindow 无法进入窗口服务器的当前 Space（`onscreen=false` 永不显示，三层取证：AppKit 回读正常 / CGWindowList 差分 / 分屏截图），故 macOS 端闪光由 `mykvm --flash x y w h` 独立子进程执行（单实例锁之前分支、NSApp accessory、2s 自退出），Windows 端保持进程内分层窗实现不变。另修复 `setLevel:`/`setCollectionBehavior:` 的整数 ABI 漂移（f64 传参进错寄存器）。清理提交后用户真机确认外接屏光圈正常。
- 经验沉淀：窗口可见性问题用 CGWindowList 差分 + `screencapture -D` 分屏截图直取事实；objc2 数值型 setter 在 macOS 27 一律"设+回读校验"；CGWindowList 差分必须做前后对照（存量辅助窗曾误判为缺陷产物）。

**验收要点**

1. 点选 Mac 每块本机屏（含全部外接屏）：对应物理屏都闪蓝色光圈，约 1.4s 自动消失；点击穿透不影响正常使用。
2. 连续快速点击多块屏：各自独立闪烁、独立消失，无报错。
3. 点选远端（GT37）磁贴：被控机对应屏闪光圈（需 GT37 升级到含 `fa5f6fc` 及之后的构建）。
4. 日志：每次点选有一条 `screen indicator covering display at cocoa ...`（匹配到的目标屏 frame）。

## BUG-007 拔插孪生扩展屏后，「显示器布局」两屏顺序变化，鼠标穿越出错

- 类型：Bug　严重度：高　状态：待排查　记录日期：2026-11-25
- 发现方式：真机使用（用户报告）
- 编号说明：BUG-006 已被「孪生屏换位空气墙」占用（登记在分支 `fix/display-identity-airwall` 的复盘文档，未单列进本表），本条目从 BUG-007 起编。

**现象**

- Mac 端外接两块**上下垂直布置**的扩展屏；拔下其中一块、再插回后，两块屏在软件「显示器布局」中的顺序（上下关系）发生变化。
- 顺序变化后鼠标穿越逻辑出错（穿越去向/落点与布局预期不符）。

**复现步骤（待补全）**

1. Mac 端外接两块上下垂直布置的扩展屏，布局中摆放正常、上下穿越正常。
2. 拔下其中一块扩展屏的视频线（另一块保持连接）。
3. 重新插回。
4. 观察「显示器布局」：两块扩展屏的顺序（上下槽位/编号）互换；鼠标上下穿越行为随之出错。

**期望**：拔插任一扩展屏后，每块屏都应绑回自己原来的布局位置与身份，穿越不受影响。

**影响**：多屏（尤其同型号孪生屏）热插拔后穿越静默出错，用户需手动重排布局才能恢复；发现/连接状态一切正常，无从判断原因。与 BUG-003/004 同属「布局几何/身份错位 → 穿越失效」表象，但触发路径是显示器热插拔 + 屏幕身份错绑，命中面广（换线、换口、合盖唤醒都可能触发）。

**初步线索（未验证，仅供排查起点）**

- 屏幕身份是**枚举序号**：`detect_local_screens`（`src-tauri/src/lib.rs:7850`）为每块屏生成 `local-display-{index+1}`，index 来自 `available_monitors()` 的枚举顺序——拔插后 macOS 重新枚举/排列，序号与物理屏的对应关系不保证稳定。
- 拔插后的身份/位置回绑在 `restore_local_screen_layout`（`src-tauri/src/lib.rs:8019`）：按 `name / 尺寸 / id` 三级匹配把保存的画布位置绑回检测到的屏；代码作者注释已预警「identical names and dimensions retain enumeration order; use OS display UUIDs…」。**两块同名同分辨率的孪生屏**在此退化为按枚举顺序配对——保存的画布位置（上下槽位）绑到「现在枚举到第几个」而非物理屏，两屏在布局中的顺序随之互换。
- 顺序互换后，穿越判定（`build_input_targets` / `touching_edge`，`src-tauri/src/input.rs:2319` / `:2433`）使用的画布邻接关系与物理屏真实上下关系不再一致 → 穿越去向出错。
- 若两块扩展屏**并非**同型号（名字/分辨率可区分），上述匹配应能正确区分，需另行取证（如 UI 按 id 排序展示导致的「顺序」表象、或其它重排路径）。

**关联**：BUG-006（孪生屏换位空气墙 + 死端长在线，登记在分支 `fix/display-identity-airwall` 的 `Doc/lessons/2026-11-BUG006-孪生屏换位空气墙复盘.md`，已修复待验收）——**本条目极可能是 BUG-006 的复现/未覆盖场景**（尤其上下垂直布置，或 EDID serial=0 孪生屏走降级路径时仍会换位）；需确认复现所用构建是否含该分支修复后再定去向：老构建复现 → 并入 BUG-006 验收；含修复的构建仍复现 → 升级为 BUG-006 验收缺口（修复未覆盖本场景）。另关联 BUG-003/004（同表象不同触发路径）。

## BUG-008 Halo 光环在扭头切屏/保存布局后消失（画板坐标被当 CG 原生坐标）

- 类型：Bug　严重度：高　状态：待验收　记录日期：2026-11-26
- 发现方式：真机使用（用户报告「Halo 光环在扭头后消失」；与 11-07「回看 mac 屏光环消失」同源）

**现象**

- FocusHalo 光环在扭头切屏（region 切换）后从屏幕上消失，之后怎么切换都不恢复；重开应用/重开跟踪后光环复现，再切一次又消失。
- 同一缺陷的另一触发路径：保存布局（`save_layout` → `SetScreens`）后光环同样消失。

**定位结论（2026-11-26，CGWindowList 窗口取证 + 日志实锤）**

- **画板坐标 ≠ CG 原生坐标**：本机两块屏的画板位置相对 CG 恒定平移 `(-3036,-448)`（两屏平移量一致，实测）。分叉不是 11-25 才有——轮转日志显示 **11-07 联调期画板已在 `(17160,5120)`**（CG 在 `(0,0)`，差 ~17000，与 070f9fc 复盘里「板面坐标系各自本地化」一致）；此后每次拔插/重排只是换了平移量。`apply_detected_local_screens` 保留画布 x/y 只刷新宽高，画板与 CG 只会越走越远。
- **mac 端 halo 把画板当 CG 恒等**：引擎初始几何来自 `native_layout`（真 CG），而 `halo_screen_entries` 屏幕表来自画板（`halo_native_origin` mac 分支恒等返回 `screen.x`）→ 两者几何对不上 → 保存布局/region 切换触发「tracked screen left the layout」重锚到画板矩形（日志 11-26 03:12:13 实锤）→ 光环窗被摆到「画板坐标解释的 CG 位置」`(-2350,-27)`，两块真实显示器均不覆盖（CGWindowList：`onscreen=true` 但落在死区，肉眼不可见），此后所有切换都停在错误坐标上。**23dd6b0 采样看到的「y=6032、屏底 6102」正是画板坐标**（当时画板屏底 = 5120+982），旧复盘归因于 norm 投影出屏只说对了一半——更深一层是整套坐标空间错位。
- **同族连带缺陷（一并修复）**：
  1. region 提交光标 warp 落点 `(-1524,534)` 同样出屏；且 `board_to_native` 把 Retina `scale=2.0` 乘进本应 points 恒等的换算（warp.rs 文档自己写明 "On macOS scale is 1"）——转头落点/光标跳转验收项长期不过的第二层根因。
  2. mac 窗口枚举假设「CG == 画板」直接透传帧（`windows_layer/macos.rs`），分叉后命中测试点空间与帧空间错位，dwell 切窗/候选边框跟着错。
  3. 校准向导 badge（`halo_screen_cal_begin`）同拿画板当 native，分叉后向导徽标飞出屏。
- 接收侧 `halo_focus_screens_with_native_geometry` 早已是正确模式（注释原话 "Board coordinates are not native desktop coordinates"），**引擎路径漏改**——本次修复就是把引擎四条路径拉回同一契约。

**修复（分支 `feature/halo-screen-warp`，基于 main `2170fad`）**

- 引擎屏幕表 / 初始几何 / P0 测试钩子 / 校准 badge 统一「board(画布) + native(检测)」规范对，且 tracking 几何与对应 entry 字节相等（杜绝首帧 `SetScreens` 误判重锚）；
- mac 窗口枚举帧经 `native_rect_to_logical` 转画板空间（Windows 语义不变）；
- 新增 `halo_geometry_scale`：mac 的 native/board 比率恒 1.0（CG points），修 warp/land 的 2× 偏移；Windows DPI 透传不变。
- 验证：619 测试全绿（+3：画板分叉、tracking==entry、scale 契约）；装机后连续 `save_layout` **无 re-anchoring 日志**、CGWindowList 复核光环窗 `onscreen=true` 且落在内建屏内并随视线移动。

**验收要点**

1. 扭头切到本机另一块屏 / 对端屏：光环始终可见；切到对端屏时停靠共享边缘，回看即刻滑回注视点。
2. region 提交的光标跳转落在目标屏内（不再出屏/落错屏）。
3. 保存布局、拔插屏后光环不消失。
4. **前置**：当前校准因拓扑变化（11-26 又换了外接屏组合）被门控（日志 `multi-screen switching suspended until recalibration`），需先跑一遍多屏校准向导恢复 region 切换——向导各屏徽标应显示在对应物理屏正确位置（badge 修复的验收点）。

**关联**：BUG-007（拔插屏是画板分叉/平移量变化的触发源）、BUG-005（macOS 27 窗口可见性家族，取证方法沿用 CGWindowList 差分）。
