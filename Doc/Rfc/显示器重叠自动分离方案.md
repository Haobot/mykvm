# MyKVM 显示器重叠自动分离方案

- 日期：2026-10-30
- 状态：待实施
- 基线：`main @ c552e29`
- 场景：Windows（server/控制端）与 macOS（client/被控端）互连，任意一端带扩展显示器
- 现象：布局画布上，扩展显示器与另一台电脑的显示器区域重叠后，鼠标无法从本机穿到正确的远端屏幕

## 0. 结论摘要（TL;DR）

1. 三处叠加造成「重叠即卡死」：
   - `screens_from_peer`（`src-tauri/src/lib.rs:8614-8619`）把远端屏幕坐标**归一化到 (0,0)**，与本机主屏 (0,0) 天然完全重叠，一配对就重叠；
   - 拖拽结束时吸合失败会**回退到拖拽起点**（`src/App.tsx:1239-1244`），起点本就重叠 → 永远摆脱不了重叠；
   - `build_input_targets`（`src-tauri/src/input.rs:2318-2321`）对与本机屏幕重叠的远端屏幕**直接跳过**，不生成穿越目标 → 移不过去。
2. 修复策略（已与用户确认）：重叠时**沿重叠量较小的轴把屏幕推开最少距离**，分离为**相切贴边**；分离后自然形成贴边关系，即可正常穿越。
3. 改动分两层：前端 `layout.ts` 为主防线（拖拽/键盘调整后消解重叠），Rust `screens_from_peer` 负责首次摆放避让。
4. 穿越方向判定（`touching_edge` / `is_crossing_screen`）**不改动**：只要不重叠且贴边，穿越即正常；`build_input_targets` 的「重叠跳过」保留为安全网。

## 1. 现象与根因

### 1.1 现象

- 布局画布上，远端设备的显示器（或本机扩展显示器）与另一块屏幕的矩形区域**重叠**。
- 此时把鼠标推向该方向无法进入对应远端屏幕；日志无报错，发现/QUIC 均正常。
- 手动拖拽试图分开时，松手又「弹回」重叠状态。

### 1.2 根因（代码定位）

| # | 位置 | 行为 | 后果 |
| --- | --- | --- | --- |
| 1 | `lib.rs:8582-8627` `screens_from_peer` | 新建屏幕坐标取 `peer_screen.x - peer_min_x`（即远端桌面左上角对齐到本地 (0,0)） | 与本机主屏 (0,0) 完全重叠 |
| 2 | `src/layout.ts:45-99` `snapOverlappingScreenPosition` | 吸合结果仍重叠时返回 `null`（`layout.ts:98`） | 调用方 `App.tsx:1239-1244` 回退 `startPosition`；起点重叠则死锁 |
| 3 | `src-tauri/src/input.rs:2318-2321` `build_input_targets` | `if screens_overlap(...) { continue }` | 重叠屏幕不生成 `InputTarget`，无法穿越 |

补充：`touching_edge`（`input.rs:2399-2445`）要求两屏**边缘对齐**（`near`，容差 `EDGE_TOLERANCE`）且投影重叠（`ranges_overlap`）。重叠布局下边缘不对齐，即便不跳过也判不出贴边。

## 2. 目标与非目标

### 2.1 目标

1. 布局中任意两块屏幕**永不重叠**；出现重叠时自动分离为**相切贴边**（最小位移）。
2. 分离后立即形成可穿越的贴边关系，鼠标能正常穿到目标屏幕并返回。
3. 不再出现「拖拽后弹回重叠起点」。

### 2.2 非目标

- 不改动穿越方向判定算法、协议与 wire 坐标语义。
- 不引入「一键自动排列」等新交互（本次不做，后续可另立）。
- 不调整吸附容差 `SNAP_TOLERANCE` / `EDGE_TOLERANCE` 的既有取值。

## 3. 设计

核心工具：**最小距离矩形分离**。对一对重叠矩形 `A`（移动方）、`B`：
- 水平重叠 `overlapX = min(A.right, B.right) - max(A.left, B.left)`
- 垂直重叠 `overlapY = min(A.bottom, B.bottom) - max(A.top, B.top)`
- 取较小者对应的轴，把 `A` 沿该轴推开「该重叠量」：方向由两屏中心关系决定（`A` 中心在 `B` 中心左/上侧则推向对应外侧，反之推向内侧），使两矩形恰好相切。
- 推开后另一维保持原有重叠 → 相切边上投影重叠区仍然充足 → `touching_edge` 成立 → 可穿越。

### 3.1 前端（主防线，`src/layout.ts`）

- 新增 `separateOverlappingScreens(layout, screenId): LayoutState`
  - 迭代：每次找出与 `screenId` 重叠面积最大的屏幕，沿最小重叠轴推开至相切；重复直到无重叠或迭代次数达到屏幕总数（防死循环）。
- `src/App.tsx` `endDrag`（`1227-1254`）：拖拽结束后调用 `separateOverlappingScreens`，**替换**现有「吸合失败 → 回退起点」分支。
- `src/App.tsx` `handleScreenKeyDown`（`1545-1579`）：键盘微调后若重叠，改为调用分离函数，而不是直接 `return layoutState` 拒绝。
- 保留 `snapScreenPosition` 的吸附体验（拖拽时的磁吸不变）。

### 3.2 Rust（首次摆放避让，`src-tauri/src/lib.rs`）

- `screens_from_peer`（`8582-8627`）：新建屏幕（无用户既有坐标）时，若与**本机屏幕**重叠，按同一「最小重叠轴推开」规则摆放到相切位置，保证首次配对即无重叠、且相切贴边。
- 新增 `separate_layout_screen_overlaps`：在 `apply_peer_presence` 收尾对所有**非本机屏幕**做一次归一化，纠正旧 `layout.json` 中已保存的重叠。它同时覆盖「启动加载布局」与「运行中刷新对端」两条路径，且重叠消除后为幂等空操作。
- `build_input_targets`（`input.rs:2285-2348`）：**保持**「重叠跳过」不变，作为安全网（正常路径不再触发）。

## 4. 验收标准

1. 首次配对（远端屏幕默认落点与本机重叠）后，画布上的两块屏幕**自动分离且相切贴边**，无需手动拖拽。
2. 从本机屏幕边缘推向远端屏幕方向，可正常穿越；从远端回到本机边缘，可正常返回。
3. 手动把远端屏幕拖到与本机重叠处松手，屏幕自动分离到相切贴边，**不再弹回重叠起点**。
4. 三屏及以上（本机双屏 + 远端）连锁重叠时，分离后仍无两两重叠。

## 5. 测试

- 前端 `src/layout.test.ts`（新增）：
  - 完全重叠（同尺寸、同原点）→ 分离后相切、无重叠；
  - 部分重叠 → 沿最小重叠轴分离、位移最小；
  - 三屏连锁重叠 → 迭代收敛、无两两重叠。
- Rust `src-tauri/src/input.rs` 单测：
  - 分离后的远端屏幕能生成 `InputTarget`（原 `input_targets_ignore_overlapping_remote_screens` 的对照用例）；
- Rust `src-tauri/src/lib.rs` 单测：
  - `screens_from_peer` 首次摆放避让本机屏幕。
- 真机：Windows 控制端推送至 Mac，跨边缘穿越与返回均正常。
