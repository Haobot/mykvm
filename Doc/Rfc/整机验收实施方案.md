# 整机验收实施方案:设备状态丢失修复 + 唤醒闪断整改

> 范围:两轮修复的真机验收——`a78ec09`/`42a564b`(P0-1 陈旧合并 / P0-2 弱匹配+id 跟随 / P0-3 证书漂移弹窗)+ `83a2ae0`(P1-2 时钟跳变宽限期)。
> 执行人:委托方(需 Mac+Win 两台真机);失败定位与复核:评审 AI。
> 预计耗时:核心用例约 40 分钟(不含睡眠等待);全程建议录屏留证。

## 一、环境与版本准备

1. **两机安装同一 main 构建**(含全部修复):
   - Mac:`npm run mac:build-install`(等价 `npm run tauri:build:mac-arm && sh scripts/install-mac-app.sh`);
   - Win:安装对应 release(开发 AI 交付的 `fix:` 已触发发版)或 Windows 构建;
   - 版本核对:两机应用内「诊断」页 appVersion 一致。
2. **基线状态**(不满足先修好再开始):两机已配对、鼠标能跨屏、剪贴板正常;Mac 端设备列表 Win 设备显示在线/已就绪。
3. **备份**:Mac 端 `cp ~/Library/Application\ Support/com.xzhpl.mykvm/layout.json ~/layout-backup.json`(Win 侧同理备份其配置目录 layout.json)。
4. **日志窗口**(Mac 终端常开):
   `tail -f ~/Library/Logs/com.xzhpl.mykvm/mykvm.log | grep --line-buffered -E 'discovery|device id followed|weak match|unmatched|prune|pair'`
   Win 侧日志/配置目录:应用内「诊断」页一键打开(Windows 下配置目录含 `quic-transport-cert.der`/`quic-transport-key.der`)。
5. **观察手段**:S1/S4 需要盯着 Mac 屏幕(弹窗只出现一次、闪断一闪而过)——手机录屏 Mac 屏幕最稳。

## 二、用例(步骤 → 预期 → 评价标准)

### S1 证书轮换 → 自动弹窗 + 一键修复【阻塞级】
1. Win 端完全退出 MyKVM;删除 Win 配置目录的 `quic-transport-cert.der` 与 `quic-transport-key.der`;重启 Win 应用。
2. 观察 Mac 屏幕与日志。

**预期**:≤10s 内 Mac 自动弹「设备证书已变化」(只弹一次);peer 行有「证书已变化」徽标。点「一键修复」→ Win 屏显验证码 → 输入 → 设备原位恢复在线/已就绪,弹窗自动消失。
**评价标准**:
- ✅ 弹窗自动出现且**30 秒内不因轮询重开**(手动关一次验证:关后不再弹);
- ✅ 修复后设备 name/颜色/指针滚轮速度/屏幕 x/y 摆放**全部保留**(对照 layout.json 备份,仅 id/证书/host 变新);
- ✅ 修复后鼠标能跨到 Win;
- ✅ 「稍后处理」路径复测一次(重做步骤 1):点稍后处理后本次不再弹、徽标仍在,再轮换一次证书后可再弹。
- ❌ 失败判定:弹窗不出现 / 反复重开 / 修复后丢摆放或丢速度 / 修复后仍不能控制。

### S2 IP 漂移 → id 跟随、自动恢复【阻塞级】
1. 把 Win 网络地址改到同网段另一 IP(静态 IP 切换最稳;或路由器 DHCP 绑定换绑),重启 Win 应用。
2. 观察 Mac 日志与设备列表。

**预期**:≤3s 设备自动恢复在线(**不弹窗、无需任何操作**);日志出现 `device id followed discovery drift old_id=... new_id=...`;layout.json 中该设备 id 已更新、屏幕 x/y 不变;鼠标立即可跨屏。
**评价标准**:
- ✅ 自动恢复,无人工干预;✅ id 跟随日志出现;✅ 摆放不丢;✅ 立即可控制;
- ✅ 手动添加(source=manual)的设备条目 id/host 不变(如有此类条目)。
- ❌ 失败判定:显示离线 / 弹了证书弹窗(key 未变不该弹)/ 摆放重置。

### S3 陈旧快照覆盖防护【阻塞级】
1. 确认 Win 在线;在 Mac 端记录 layout.json 中 Win 设备的 key/host/ports(复制一份 `/tmp/layout-before.json`)。
2. Win 端退出应用(设备转离线);**此时在 Mac 端任意改一项设置并保存**(如主题/热键)。
3. 重启 Win 应用(回到在线)。

**预期**:Win 自动恢复在线、无需重新配对;对比 layout.json:key/host/ports **未被保存操作回退**。
**评价标准**:✅ 恢复在线;✅ 字段未回退;✅ 附带检查:两端都退出后 layout.json 里所有设备 `online:false, inputReady:false`(瞬态不落盘)。
- ❌ 失败判定:恢复后离线/需重新配对,key 或 host 变回旧值。

### S4 睡眠唤醒无闪断——长睡眠【阻塞级】
1. 两机在线;记下时间戳;Mac 合盖睡眠 **6~10 分钟**(⚠ 必须 >5 分钟:跳变阈值是严格大于 300 秒,正好 5 分钟不触发);期间可让 Win 保持运行。
2. 唤醒 Mac,盯屏幕 + 日志 30 秒。

**预期**:设备列表**不出现集体「离线」闪断**;日志序列:`discovery prune skipped after apparent clock jump ... grace_until_ms=...` → ≤5s 内 `discovery peer updated` 刷新;不出现大批 `discovery peer stale`。
**评价标准**:✅ 无闪断;✅ 日志序列符合;✅ 唤醒后立即可跨屏。
- ❌ 失败判定:设备集体变离线又恢复 / 大批 stale 日志。

### S5 睡眠唤醒——中短睡眠(2 分钟档)【阻塞级,P1-2b 已合入(4edb870)】
1. 同 S4,但睡眠 **约 2 分钟**后唤醒。

**预期(P1-2b 合入后)**:无闪断;日志同样出现宽限序列(grace_until_ms)。P1-2b 未合入时按记录级记录闪断幅度(当前实现 ≤3s,见 §三.1)。
**评价标准**:无闪断 + 日志序列符合 → 通过;闪断 >10s 无论何时都升级为缺陷。

### S6 正常回归与不骚扰【阻塞级】
1. 正常使用 15~30 分钟:跨屏鼠标/键盘、Alt+C/V 剪贴板、拖文件传输、调整屏幕摆放并保存重启应用后仍在。
2. 期间不触碰任何修复弹窗;观察是否有**误弹窗**。

**评价标准**:✅ 全部功能正常;✅ 无任何"证书已变化"误弹(key 未变);✅ 诊断报告 `unmatched devices: 0`(全部匹配时);✅ 弹窗零骚扰。
- ❌ 失败判定:任一回归功能异常 / 出现误弹窗。

### S7(可选)弱匹配显示恢复【记录级】
构造:Win 端清证书但**先不重启 Mac 侧观测**(或用一台旧版/手工添加的无证书设备条目)。预期:设备仍显示在线(名称/主机名弱匹配)但带"证书已变化"提示,一键修复可闭环。验证"显示恢复不给信任"。

## 三、已知残余(预期行为,避免误判为缺陷)

1. **中短睡眠(90s~5min)唤醒仍闪断**:跳变保护阈值 `CLOCK_JUMP_GUARD_MS = 300_000` 严格大于 5 分钟才触发宽限;睡眠 90s~5min 的唤醒走正常 TTL,peers 被删后靠 announce(≤3s)重建,**闪断 ≤3s 依旧**。属实现覆盖缺口(目标是消除所有唤醒闪断)。✅ **已由 P1-2b 修复(commit `4edb870`)**:触发阈值收紧为 60s(改名 `PRUNE_GAP_GRACE_TRIGGER_MS`,< TTL 90s,任意 ≥TTL 停顿必触发宽限),S5 即该缺口的复现器,现已转阻塞级。
2. 真已下线的对端在唤醒后多显示在线 ≤5s(宽限期内),随后转离线——正常。
3. ~~日志措辞瑕疵~~ ✅ 已由 P1-2b 修复:`discovery prune expired N peers` 中性措辞,不再误导。

## 四、评价标准汇总与判定规则

| 级别 | 用例 | 判定 |
|---|---|---|
| 阻塞级 | S1 S2 S3 S4 S6 | **全部通过 → 整机验收通过**;任一失败 → 不通过 |
| 阻塞级(P1-2b 合入后追加) | S5 | 合入后按阻塞级判;未合入降为记录级 |

失败处理:① 保留证据(时间戳 + 日志窗口输出 + layout.json 对比 + 录屏);② 发给评审 AI 定位归属(哪一轮哪一组件);③ 交开发 AI 修复后**重跑该用例 + S6 回归**。

## 五、异常恢复手册

- 弹窗/设备异常卡住:Mac 端设备设置 → 该设备「重新配对」(已优先实时地址);
- 配置错乱:退出应用,用 `~/layout-backup.json` 覆盖回 layout.json 后重启;
- 重装后权限丢失(坑 1):系统设置重授辅助功能/输入监控,必要时 `tccutil reset Accessibility` 后重启应用;日志须见 `discovery started` 与数秒内 `discovery peer updated`;
- Win 端彻底重来:应用内「重置配对」→ 两机重新配对。
