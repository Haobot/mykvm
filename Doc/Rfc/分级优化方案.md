# MyKVM 分级优化方案

- 日期：2026-10-13
- 状态：草案（待评审）
- 依据：《MyKVM 架构与功能逻辑分析》（2026-10-13，基于 v0.9.13 / main@0f93671）
- 排序原则：正确性 > 可读性 > 性能 > 简洁性；所有行为变更遵循 TDD（先失败测试后实现）；协议演进遵循"新增可选字段 + 能力探测降级"护栏

## 总览

| 阶段 | 周期 | 主题 | 核心目标 |
| --- | --- | --- | --- |
| 短期 | 0-2 个迭代（约 2-4 周） | 止血与护栏 | 修复已证实的缺陷面（安全细节、内存泄漏、副作用 bug），补 CI 护栏，零协议变更 |
| 中期 | 1-3 个月 | 结构与性能 | 拆解三大巨型文件（lib.rs / input.rs / App.tsx），文件传输流水线化，剪贴板图像扩容 |
| 长期 | 3-6 个月以上 | 平台与安全 | Linux 输入后端（#11/#31），发现通道签名，协议治理与跨机 e2e 测试基建 |

依赖关系：短期第 5 项（CI 护栏）必须最先落地；中期 1/2 依赖护栏就位；中期 3/4 涉及协议演进，需沿用 `directory-probe` 式能力探测保证旧端可降级；长期各项相互独立，可按资源并行。

## 一、短期（0-2 个迭代）：止血与护栏

原则：不动协议、不动模块结构，只修已证实的问题。每项独立成 commit，可随时回退。

### 1.1 安全细节修复

**目标**：消除两个已知的安全细节缺陷，不改变信任模型。

1. `pair_secret` 明文等值比较改为恒定时间比较（`lib.rs:8249-8251`）。
   - 路径：引入 `subtle` crate（或手写 `consttime_eq`，约 10 行，避免加依赖）；先写行为等价单测（相同/不同长度/不同前缀），再替换实现。
2. 无凭据输入包按源地址 5 秒放行窗口（`input.rs:166-185`）收紧。
   - 路径：TTL 从 5s 降为 2s；仅当该源在窗口内发送过带凭据包才缓存源（已是如此则确认并文档化）；增加被放行包的 debug 计数器（接入 `performance.rs`）。

**验收**：新增单测覆盖上述行为；`cargo test` 全绿。
**风险**：TTL 收紧在弱网下可能造成首包凭据重发——凭据本就每 2s 附带一次（`input.rs:111`），影响可忽略。

### 1.2 内存与资源泄漏修复

**目标**：消除三处长期运行的泄漏面。

1. `remote_screen_points` / `local_screen_points` 只增不删（`input.rs:254-259`）。
   - 路径：先写失败测试（插入 N 个会话后断言容量有界）；实现为"会话结束时清理 + 上限 256 条 LRU 淘汰"。
2. Windows 拖拽浮层每帧 `GetDC`/`CreateDIBSection`（`windows_drag_overlay.rs:157-188`）。
   - 路径：复用 DC 与 DIB，仅 `UpdateLayeredWindow` 每帧调用；列入 1.5 的真机验证清单。
3. macOS 富文本读取的裸指针转 Vec（`rich_clipboard_macos.rs:58-66`）审计 autorelease pool 覆盖。
   - 路径：通读所有 `objc_msgSend` 调用点，确认均在 pool 内；补一条注释性测试或文档说明纪律。

**验收**：LRU 有界性有单测；真机验证清单通过（Windows 项）。

### 1.3 前端副作用修复（StrictMode 双保存）

**目标**：消除 `updateLayout` 在 setState 回调内触发 IPC 的反模式（`App.tsx:1445-1452`），StrictMode（`main.tsx:49`）下会重复调用 `persistLayout`。

- 路径：把 `persistLayout` 从 reducer 函数体移到快照变更后的 `useEffect`（以 snapshot 版本号为依赖）或事件处理函数末尾直接调用；先在 `node --test` 中写失败测试（mock invoke 计数，断言同一布局变更只保存一次）。

**验收**：回归测试通过；浏览器开发模式下拖动屏幕，Network/invoke 面板无重复 `save_layout`。

### 1.4 后端状态读取放大修复

**目标**：`layout_snapshot` 每次快照都连带做 peer 在线合并（`lib.rs:1412-1418`），前端 2s 轮询放大为每 2s 一次 O(peers) 合并。

- 路径：合并职责已在发现线程 `sync_layout_peer_presence` 中存在，快照改为纯读缓存结果；保留一次防御性合并作为兜底但节流至 1s。

**验收**：`read_runtime_status` 路径无锁内遍历合并；行为不变（在线状态展示一致）。

### 1.5 工程护栏（最先落地）

**目标**：CI 覆盖格式与 lint 静态检查，补 Windows 真机验证清单。

- 路径：
  1. `ci.yml` 增加 `cargo fmt --check` 与 `cargo clippy --workspace --all-targets --deny warnings`（当前仅有 check/test，`ci.yml:47-60`）；存量告警先集中一次清理提交。
  2. 新建 `docs/windows-drag-checklist.md`：Windows 拖拽三模块（`windows_drag.rs:16-19` 作者自述未真机验证）的手动验证清单（拖出→浮层→对端落地→取消→64 项/2GiB 边界）。
- 验收：CI 全矩阵（ubuntu/windows/macos）通过含 clippy。

### 1.6 阻塞调用治理

**目标**：`send_stream_expect_ack` 调用方最长 6s 阻塞（`quic_transport.rs:212`），审计前端命令路径上的同步等待。

- 路径：grep 全部调用点，逐个确认已 `thread::spawn` 或为 `async` 命令；将仍在命令线程上直接等待的（如 `paste_remote_clipboard`）改为 async + 超时返回错误。

**验收**：任何 Tauri 命令不再在调用线程上等待超过 1s 的网络操作。

## 二、中期（1-3 个月）：结构与性能

前提：短期护栏（clippy/fmt/真机清单）已就位。每项重构独立分支、独立 PR，全程保持 `cargo test` + `npm test` 全绿。

### 2.1 lib.rs 拆分（纯机械搬移，行为不变）

**目标**：lib.rs 从约 1.22 万行降至约 4000 行（保留 `AppRuntime`、命令注册薄层与生命周期编排），各领域逻辑归位。

| 新模块 | 搬移内容（估行数） | 证据位置 |
| --- | --- | --- |
| `discovery.rs` | 发现广播/探测/应答、PEER_TTL 剔除、配对挑战与确认（约 2500） | lib.rs:1058-1206, 9018-10050 |
| `clipboard_sync.rs` | 剪贴板轮询/编码/回声抑制/接收写入（约 1500） | lib.rs:6482-7026 |
| `file_transfer.rs` | 传输编排/分块/进度/临时文件清理（约 2000） | lib.rs:7145-7700, 8492-8700 |
| `windows_service.rs`（cfg(windows)） | 服务安装/防火墙/SID/SCM 管理约 1500 行 | lib.rs:4250-5265 |
| `tray_menu.rs` | 托盘菜单与窗口管理 | lib.rs:3284-3652 |

- 路径：按耦合度从低到高逐个搬移（windows_service → tray → clipboard_sync → file_transfer → discovery）；每次搬移用 `pub use` 保持外部符号不变，命令注册表（lib.rs:3860-3900）不动；搬移后立即全量测试并小步提交。
- 验收：每个模块拆分 PR 前后 `cargo test` 输出一致；lib.rs 行数达标；无行为 diff（可用 release 前后手测清单抽查）。

### 2.2 input.rs 拆分与会话状态收敛

**目标**：消除全局可变静态，把会话正确性从"手工复位"改为"结构化生命周期"；input.rs 降至约 5000 行。

1. 拆分模块：
   - `edge_switching.rs`：越界判定、落点折算、返回压力/冷却——纯函数化（源：input.rs:6104-6441）；
   - `input_capture_windows.rs` / `input_capture_macos.rs`：平台捕获线程与 hook/CGEventTap（源：input.rs:1430-1832, 3258-3444, 4043-4748, 5041+）;
   - `injection.rs`：`dispatch_input_command` 与平台注入族（源：input.rs:2886-3223, 7901-8628）。
2. 状态收敛（对应分析发现的 input.rs:191-196, 283-289, 483, 529, 3824 等全局静态）：
   - 全部收入 `InputRuntime` 结构体，`Arc<InputRuntime>` 传递给捕获线程；
   - `SENDER_HELD` 从全局单例改为 per-target 持有集，消除多目标并发污染（input.rs:483-489）；
   - `Arc::ptr_eq` 手工清理（input.rs:1815）随迁移简化为 Drop 语义。
- 路径：先拆 `edge_switching.rs`（纯逻辑、可表驱动测试：160px 激活带、8px 返回压力、150ms 冷却各一组用例），再收敛静态，最后拆平台文件。
- 验收：`edge_switching` 单测覆盖三个阈值参数的全部分支；全局 `static mut`/可变静态计数为零（可用 clippy 配合审查）；双平台真机冒烟（跨屏、快捷键、返回）。

### 2.3 文件传输流水线化（协议演进，双端更新）

**目标**：消除"每 256KB 块一个 stream + 全量 ack"的握手式往返（lib.rs:7617-7626，2GiB = 8192 次往返），局域网吞吐提升一个数量级。

- 方案：
  1. 新 kind `streamed-start/chunk-streamed/finish-v2`：单文件单 QUIC stream 内多块顺序写入，滑动窗口 8 块在途、块级累计确认；chunk 上限升至 1MiB；
  2. 能力协商：复用现有 `directory-probe`/`clipboard-probe` 探测机制（lib.rs:7337-7344）新增 `bulk-probe`，旧端回 reject 或不识别则自动降级旧路径（保证与 v0.9.x 互通）；
  3. 取消语义保持每 chunk 检查 `transfer_jobs` 标志（transfer_jobs.rs:12-49）。
- 路径（TDD）：
  1. 先在回环测试（本机起两个 `quic_transport` 实例）写失败测试：传输 100MiB 随机文件的吞吐下限与取消正确性；
  2. 实现新协议路径；3. 实现降级探测；4. 基准对比进 `performance.rs` 计数器。
- 验收：1ms RTT 回环下 1Gbps 链路利用率 ≥ 60%（旧路径约 20-30%）；与旧版本混布时自动降级且功能不回归；取消/断线/残留清理行为与旧路径一致。

### 2.4 剪贴板图像传输优化（协议演进）

**目标**：消除 base64 膨胀：32MiB RGBA 解码后经 base64 约 43MiB，贴近 48MiB 流上限（clipboard.rs:3-6, quic_transport.rs:33），余量过小且浪费带宽。

- 方案：`ClipboardPacket` 新增可选字段 `imageRaw`（MessagePack bin，原始字节）与可选 zstd 压缩标记；旧字段 `image`（base64）保留写兼容；接收端优先 `imageRaw`。
- 路径：失败测试先行（新旧字段互转 + 旧端收到仅 base64 的包仍可解）；发送端实现 raw+zstd；回环验证。
- 验收：32MiB 图像线上体积降至 ≤ 12MiB（典型截图 zstd 压缩比 ≥ 3.5:1）；与旧端互通；序列号/回声抑制行为不变。

### 2.5 App.tsx 组件化拆分

**目标**：App.tsx 从约 3300 行组件（42 个 useState，App.tsx:190-3500）降至 < 800 行，消除全树重渲。

- 路径：
  1. 先抽无状态渲染块为 `memo` 组件：`LayoutCanvas`（2424-2537）、`DeviceList`（2539-2720）、`SettingsPanel`（2722-3328）、`PairingDialog`（3340-3446）、`TransferToast`（2108-2175）；
  2. 全局状态收敛：布局快照走 `useReducer`，派生数据（在线合成、版本兼容提示）改为 selector 计算；
  3. 每抽一个组件跑 `npm test` + 浏览器冒烟（布局拖拽/吸附、设备添加、设置保存）。
- 验收：App.tsx 行数达标；React DevTools Profiler 中拖动屏幕时 SettingsPanel 不重渲；StrictMode 下无重复 IPC（依赖 1.3）。

### 2.6 状态同步事件化（削减轮询）

**目标**：前端 2s 全量轮询（App.tsx:672）降为事件驱动 + 慢速兜底。

- 路径：扩大 `runtime-state-changed` 推送范围（peers 变化、配对状态机迁移处增加 notify，均已在发现线程持有写锁的位置插入）；前端轮询间隔放宽到 10s 兜底；性能采样（3s）与诊断（5s）仅在设置页可见时拉取。
- 验收：设备上线/下线在 1s 内反映到 UI；空闲时 invoke 频率下降一个数量级。

## 三、长期（3-6 个月以上）：平台扩展与安全加固

### 3.1 Linux 输入后端（issue #11/#31）

- 目标：补齐 Linux 键鼠采集与注入，交付完整三平台。
- 路径（分三期）：
  1. **X11 全功能**：XI2（XRecord/XI2 raw events）捕获 + XTest 注入；剪贴板 wl-paste/xclip 已有雏形（clipboard.rs:466-491）；
  2. **Wayland 只读**：剪贴板同步 + 被控指示（无注入）；
  3. **Wayland 注入**：libei + libportal RemoteDesktop 门户授权路径。
- 基建：CI ubuntu job 增加 Xvfb 集成测试（发现→配对→注入模拟）。
- 验收：X11 下全功能对等 Win/mac；Wayland 门户流程有截图级测试文档。

### 3.2 发现通道安全加固

- 目标：消除"明文未认证发现"这一最大攻击面（README 已声明限制），升级为签名发现。
- 路径：
  1. announce/reply 报文用本端传输证书私钥签名（rmp 字段新增 `sig`），已配对端用 pin 的公钥验签，未配对设备标记 `unverified` 并在 UI 提示；
  2. `pair_secret` 迁出明文 layout.json：macOS Keychain / Windows DPAPI / Linux libsecret，读取层封装 + 迁移逻辑（首次启动搬运并删除明文）；
  3. 配对码暴力尝试限速已有（60s/5 次，lib.rs:80-81），补充按源 IP 的全局限速。
- 验收：伪造 announce（无签名/错误签名）被拒绝且有日志；明文 secret 不再落盘；老配置自动迁移。

### 3.3 协议治理与版本化

- 目标：四个协议（discovery/input/clipboard/file-transfer）帧格式集中治理，杜绝散落定义。
- 路径：
  1. 新建 `protocol.rs` 汇总全部帧类型与常量（现散布 lib.rs:75-98, 608-640、input.rs:335-355、shared_input.rs 等），模块只做逻辑不做定义；
  2. 撰写 `docs/protocol.md`：帧表、版本协商矩阵、弃用策略（"可选字段新增→一个次版本→旧字段移除"）；
  3. 引入 cargo-fuzz 对 msgpack 解码入口（datagram/stream）做模糊测试。
- 验收：协议定义单一来源；fuzz 无 crash 跑通 24h 基线。

### 3.4 跨机 e2e 测试与性能基准

- 目标：把"作者真机手测"升级为自动化回归。
- 路径：
  1. e2e 框架：两台 CI VM（windows + ubuntu）或单机多用户会话，脚本化跑全链路：发现→配对→输入注入→剪贴板→文件传输→断线重连；
  2. 性能基准进 CI nightly：输入端到端延迟 P99（事件时间戳穿透）、文件吞吐（复用 2.3 基准）、剪贴板同步时延；结果出趋势报表。
- 验收：nightly 基准回归超阈值自动开 issue；e2e 覆盖全部 5 条链路。

### 3.5 多设备拓扑（>2 台）

- 目标：支持 3+ 台机器的键鼠漫游。
- 路径：邻接模型已是按边生成 `InputTarget`（input.rs:207-228），中期 2.2 的 per-target `SENDER_HELD` 已消除并发污染前提；剩余工作为控制权仲裁（同一时刻仅一个 ActiveTarget，切换加锁序）与布局画布多群组校验。
- 验收：三机环形布局下顺时针漫游无粘滞；任意一机离线不影响其余两机。

### 3.6 研究方向（不承诺）

- 屏幕串流（KVM 的 "V"）与音频跟随——涉及带宽/编解码权衡，待输入链路稳定后评估；
- 输入链路 FEC/自适应码率——当前 QUIC datagram 丢弃旧包策略已够用。

## 五、全局风险与回退策略

1. **重构引入行为回归**：所有搬移 PR 要求测试输出逐字节对账 + 真机冒烟清单；每步小提交可单独 revert。
2. **协议演进造成新旧不互通**：一切新能力必须带 probe 降级路径，混布测试（新版↔v0.9.x）进入验收标准。
3. **Windows 原生模块验证不足**：短期先补真机清单，中期重构该三模块前必须完成清单至少一轮全量执行。
4. **范围蔓延**：长期 3.6 明确不承诺；每阶段结束做一次回顾，未达标的项显式延期而非顺延塞入。
