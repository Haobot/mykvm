# 网络抗干扰与多接口持续连接方案

- 状态：待评审
- 日期：2026-11-04
- 背景：[2026-11-04 断连调查](../lessons/)（discovery 卡死修复分支 `fix/discovery-probe-write-timeout`）与当日 AP 层 UDP 黑洞事件

## 1. 背景与证据

办公/家庭局域网常无法做 DHCP 静态绑定，本方案针对已实测的三类网络扰动设计：

| 扰动类型 | 实测证据（2026-11-04 及之前） | 当前系统的反应 |
|---|---|---|
| DHCP 漂移（换 IP） | Mac 一天内漂过 `.42/.65/.44/.45/.135`；10-29 `.42↔.65` 来回跳 | peer id 随之变化；directed 目标失效退化为广播；QUIC 缓存地址失效（timed out + 3s mute） |
| AP 层 UDP 黑洞（ICMP 通、UDP 双向丢） | 11:53:50 UTC 起两机 UDP 全断约 40 分钟，ping 正常 | 无检测、无报告、无绕行，仅靠等待自愈 |
| 多接口（WiFi+网线/USB 网卡） | Mac 有 en0(WiFi)+en4/5/6(USB)；Win 有 WiFi+Hyper-V vEthernet+Tailscale | `local_ip_address()` 只选一个"主 IP"，另一接口地址完全不可见；主接口摇摆导致 id/地址摇摆（Mac `.42↔.65` 即双接口竞争）；headless 服务实例曾探测失败报 `127.0.0.1` |

前置修复（本方案依赖，已在 `fix/discovery-probe-write-timeout` 分支）：发现链路全部 UDP socket 补写超时 + 发现线程卡死看门狗。它保证扰动不再卡死线程，本方案解决扰动下的**快速感知、快速恢复、多路径降险**。

## 2. 目标与非目标

**目标**
- G1 IP 漂移不中断服务：地址变化后秒级完成 announce 更新与 QUIC 重连，无需重新配对、无需用户干预。
- G2 多接口识别与兼容：WiFi+网线同连时两个地址都被识别、都被 announce，任一接口断另一路接管；接口地址探测不再摇摆、不再回退 `127.0.0.1`。
- G3 UDP 黑洞降险与明确报告：多路径（多地址×多端口×源端口轮换）降低全断概率；断链可检测、可区分、UI 与日志明确。
- G4 兼容与安全：老版本对端混跑不崩；证书 pin / cluster_id / 配对关系等安全模型不变。

**非目标**
- 不追求跨网段/跨路由（当前为同网段 LAN 设计；公网 NAT 穿透另行立项）。
- 不解决 AP 硬件故障本身——AP 持续丢弃两机间一切 UDP 时任何软件无解，本方案只保证链路恢复后秒级自愈。
- 不改 QUIC 库（quinn 0.11），只在其配置与调用层做文章。

## 3. 分层设计

### A. 地址层：多地址枚举与排序（多接口兼容的根基）

新增 `local_ip_addresses() -> Vec<IpCandidate>`，返回**有序候选列表**替代现单值 `local_ip_address()`（lib.rs:5244-5259）：

- 枚举：Windows `GetAdaptersAddresses` / macOS `getifaddrs`（或跨平台 if-addrs crate，评审定）。
- 过滤：排除 loopback（127./::1）、TUN/TAP（utun*、Tailscale、IfType 虚拟）、link-local（169.254）、蓝牙/PAN；Hyper-V/WSL 虚拟交换机（172.x NAT 段）默认排除。
- 排序（决定主展示地址与 id 派生）：① 与任一已配对对端地址同网段者优先；② 有默认路由的接口次之；③ 其余。排序键稳定化，杜绝摇摆。
- `local_peer_id` 继续基于**排序后的首选地址**派生（保持既有 id 语义与漂移跟随机制），但 announce 携带全量列表（见 B）。

### B. 发现层：announce 携带地址列表 + directed 多路径

- `LanPeer` 新增 `ips: Vec<String>`（默认空，msgpack 向后兼容，旧版解码忽略未知字段——需加跨版本编解码测试）。
- announce/probe/reply 全部携带 `ips`；对端 merge 时合并进 peer 记录。
- `known_peer_discovery_targets`（lib.rs:10389）从「单 ip + host」扩展为「ips 全列表 × 端口 span」的并集（上限保护：单 peer 最多 N×span 个目标，N≤4，防地址风暴）。
- 效果：WiFi+网线双接口的对端有两条 directed 保活路径；任一接口 IP 变化/失效，另一路径继续，TTL 不会误判死。

### C. 感知层：地址变化秒级感知与主动恢复

- `LOCAL_IDENTITY_REFRESH_INTERVAL`（现 10s，lib.rs:5171）内做地址集合 diff：集合变化（增/删/换首选）时——
  1. 立即重发一轮 announce（广播 + 全 directed）；
  2. 对所有已配对对端立即 directed probe（不等 45s TTL 探测周期）；
  3. `log::info!("local addresses changed: [...] -> [...]")`（此前调查定下的可观测性项）。
- 唤醒场景复用同一路径：时钟跳变守卫（lib.rs:10267）触发时同样立即 announce + probe。
- P1 再引入原生事件订阅（Windows `NotifyIpInterfaceChange`/`WM_POWERBROADCAST`；macOS `NWPathMonitor`）把感知延迟从 ≤10s 压到秒级以下；P0 用轮询 diff 先行。

### D. 传输层：QUIC 多地址拨号（Happy Eyeballs）

- `establish_connection`（quic_transport.rs:981-983）对对端地址列表**并行发起**（或 250ms 间隔串行），先完成握手者胜出，其余取消；ConnectionMap 仍按 `PeerKey` 键控，胜出地址即键。
- 拨号失败的旧地址连接由既有 `forget_connection` + 健康度记录清理。
- P2 验证 quinn 连接迁移（对端源地址变化时服务端按 CID 续连），若可用则接口切换可做到输入流零中断。

### E. 状态层：断链可区分（可观测性）

- peer 状态从二值 online 扩展为三态：`online`（收到 announce/probe）/ `degraded`（TTL 内但 directed 全路径失败）/ `offline`（TTL 判死）。
- 断链事件统一日志：`"peer {name} unreachable on all paths [...] for {n}s"`（warn，去重），前端 UI 同步区分显示「对端离线」vs「网络中断（尝试恢复中）」。

### F. 带外层（P2）：BLE 蓝牙恢复信道

网络路径**全部失败**（UDP 黑洞、IP 整体漂移）时的最后恢复手段。利用两台笔记本几乎必有的蓝牙硬件，通过 BLE 交换「集群指纹 + 当前网络地址」，拿到地址后立即 UDP probe 验证 → QUIC 拨号，把恢复时间从「等链路自愈」压到约 2-5 秒。**不承载输入流**（带宽/延迟差 2~3 个数量级，仅控制面）。

平台能力（2026-11-04 核查）：

| 能力 | macOS（CoreBluetooth） | Windows（WinRT） |
|---|---|---|
| 扫描广播 | ✅ | ✅ |
| 发射广播（31B legacy payload） | ✅ | ⚠️ 可用但不支持 connectable 广播；栈跨系统更新有可靠性风险 |
| GATT 服务端（被连接） | ✅ | ❌ |
| GATT 客户端 | ✅ | ✅ |

恰配当前部署形态：Mac（服务端）做 GATT 服务端广播、Win（客户端）扫描并连接；互控双向场景退化为双向「广播摘要」模式（仍可用）。

协议与联动：
- 广播（31 字节）：`[AD头2B][Company ID 2B][cluster短哈希8B][主IPv4 4B][端口2B][序号+标志2B][校验4B]`，多地址轮转广播（每次一个，N≤4）。
- Mac GATT 自定义 service：只读 characteristic 返回完整 `ips` 列表 + `quic_port` + 证书指纹 16B。
- 触发联动（接 E 层三态）：`online` 时广播 1 次/10s（低功耗）；`degraded` 升至 1 次/2s + 开始扫描；`all-paths-failed` 时 1 次/s + 持续扫描，取到地址即验证恢复，成功后回落正常态。
- 安全：广播明文仅含 cluster 哈希与地址（无密钥材料）；蓝牙取得的地址一律视为**不可信候选**，身份最终由 QUIC 握手的证书 pin 验证（与 B 层地址列表同语义），安全模型不变。
- 降级策略：定位为「尽力而为的加速路径」，BLE 不可用/失败时**静默退回**网络路径，不引入新故障面。
- 风险：Windows BLE 栈跨更新可靠性（真机冒烟 + 运行期检测）；适配器发射能力差异（冒烟清单）；macOS 首次蓝牙权限弹窗（文档引导，一次性）；2.4GHz 与 Wi-Fi 互扰（BLE 37 广播信道跳频，实测影响小）。
- 规模：约 1000 行（Mac ~400 / Win ~400 / 联动 ~200），3-5 天含双端真机调试。

### 附：已评估未采纳——超声波邻接探测（2026-11-04）

结论：**不进主线**，记档防止重复评估。理由：

1. 速率不可行：商用系统 8~100 bps、研究级最优数百 bps~低 kbps（arXiv:2103.11261），传 32 字节令牌需 3~10 秒，与持续连接需求差 3 个数量级。
2. 物理层受限：消费级扬声器/麦克风在 20kHz 显著滚降，可用窗口约 17.5~20.5kHz；系统有损音频编解码、AGC、多径、音量为 0/耳机路由切换均破坏可用性。
3. 人耳并非零感知：18~19kHz 年轻人可闻；取 19kHz+ 则扬声器声压进一步不足，速率恶化。
4. 对 MyKVM 价值增量小：LAN 信任域 + 桌面设备固定摆位，「物理邻接」几乎恒真，信息量趋近于零；粗略距离信息 BLE RSSI 已可提供。
5. 唯一说得通的用途是首次配对的「物理邻接证明」（防中继 UX 增强），但信任 LAN 威胁模型下无中继攻击场景，收益不抵双端麦克风权限弹窗 + 音频栈适配成本。

若未来做「靠近自动配对」类 UX，再从 backlog 取出评估。

## 4. 分期

| 期 | 内容 | 预估 |
|---|---|---|
| **P0（本 RFC 批准后即可开工）** | A 多地址枚举排序 + B announce 携带 ips 与 directed 多路径 + C 地址变化 diff 即时 announce/probe 与日志 | ~300 行 + 测试，1-2 天 |
| P1 | D Happy Eyeballs 并行拨号 + 原生网络事件订阅 + E 三态展示 | ~400 行，2-3 天 |
| P2 | quinn 连接迁移验证与启用；`local_peer_id` 彻底与 IP 解耦（改用证书指纹，走 Pass 1b 跟随做存量迁移）；**F 层 BLE 带外恢复信道**（详见 §3-F） | BLE ~3-5 天，其余评估后定 |

依赖关系：P0 依赖 `fix/discovery-probe-write-timeout` 合入 main（新分支基于其后）。B 的协议字段（`ips`）一次定型，P1/P2 不再改协议。

## 5. 测试策略

- 单元：地址过滤/排序规则（mock 接口清单，含 WiFi+网线+TUN+Hyper-V 组合）；地址集合 diff 判定；`ips` 字段跨版本编解码（新包旧解码、旧包新解码）；directed 目标笛卡尔积与上限。
- 集成（既有 UDP 双进程测试框架）：双地址对端模拟（同进程绑定两个本地端口），拔掉一路后另一路保活不判死；IP 变化后一周期内 peer 记录跟随。
- BLE（P2 时点，真机冒烟清单）：双端广播互见、Mac GATT 服务端可被 Win 读取、`all-paths-failed` 触发联动自动恢复、BLE 失败静默降级不报错。
- 真机验收（Mac+Win）：①网线插拔/WiFi 开关时输入不中断或 ≤3s 恢复；②DHCP 换 IP（手动续租触发）后无需重新配对，≤10s 恢复 directed；③制造 UDP 黑洞（防火墙临时规则）期间日志出现 degraded/unreachable，解除后 ≤10s 恢复 online；④（P2 后）阻断两机间全部 UDP 期间 BLE 在 ≤10s 内完成地址交换，链路恢复后自动回切网络路径。

## 6. 风险与兼容性

- **协议兼容**：`ips` 为新增可选字段；需验证 rmp-serde 旧版本对未知字段的忽略行为，测试兜底。若不兼容则 bump `PROTOCOL_VERSION` 并做双版本握手探测。
- **地址风暴**：上限保护（N≤4/peer）+ directed 目标排序去重，避免 probe fan-out 放大（结合写超时修复的 500ms 上界，最坏 fan-out 时延可控）。
- **隐私**：announce 携带多地址与现有单地址字段同级，仅信任 LAN 内可见，不含任何密钥材料，安全模型不变（`should_send_public_announce` 注释既定边界）。
- **BLE 平台风险**（§3-F）：Windows BLE 栈跨更新可靠性、适配器差异，均以「尽力而为 + 静默降级 + 真机冒烟」缓解，不作为唯一恢复路径。
- **id 语义**：P0 不动 id 派生（继续首选地址），漂移由既有跟随机制兜住；彻底解耦放 P2，避免一次改动面过大。

## 7. 验收标准

1. Mac（WiFi+USB 网线双连）与 Win 互控：拔网线、关 WiFi、再恢复，全程无重新配对，输入中断 ≤3s。
2. 手动触发 DHCP 续租换 IP 后，≤10s 内两端的 peer 记录与 directed 路径完成更新。
3. 连续 24h 运行（含数次睡眠唤醒）：无 `discovery loop stalled`、无误判 stale（真实离线除外）、无 discovery 线程卡死。
