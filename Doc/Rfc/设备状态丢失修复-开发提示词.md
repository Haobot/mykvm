## 1. 你的任务

修复缺陷:**Mac 端(server/控制端)会丢失另一台 Win 端(client/被控端)的设备状态**——设备条目显示离线/未就绪,或设备身份(传输公钥/地址/id)与实时对端失配后**永久失联、无自愈、日志零报错**。交付经过单测验证的代码,不破坏既有安全语义。

## 3. 问题陈述与根因(已定位,实现时以此为准)

状态链路:Win 端每 3s 发 UDP announce → Mac 合并进 `peers` 列表(`merge_peer_entry`,lib.rs:9307;TTL `PEER_TTL_MS` lib.rs:83)→ 设备条目的 `online/inputReady/host/key` 由 `apply_peer_presence`→`update_device_from_peer`(lib.rs:8428/8553)按 `device_matches_peer`(lib.rs:8491)匹配决定;前端显示又按同一匹配重算一遍(`App.tsx` `applyPeerPresence`:3945、`pairingRepair.ts` `deviceMatchesPeer`:38)。前端每 2s 轮询 `load_app_state`(App.tsx:657),它先 `refresh_layout_from_disk`(lib.rs:738)用磁盘快照覆盖运行时布局。

**路径 A|身份失配 → 永久丢失(主因)**:`device_matches_peer` 在设备存有传输公钥时只做 key 严格相等、无回退(lib.rs:8491-8497)。
- Win 端证书轮换(重装/清配置重新生成证书,quic_transport.rs:501)→ Mac 存的旧 key 永远匹配不上,设备永久离线,且匹配失败导致 `update_device_from_peer` 不执行、key 永不刷新。代码注释自认:request_lan_pairing 注释(lib.rs:3006)「证书轮换后 discovery 无法再刷新它」;pairingRepair.ts:17-20「布局里的设备会一直显示离线」。
- Win 端换 IP 且设备条目无 key:设备 id 内嵌 LAN 地址会漂移(lib.rs:8802 `local_peer_id`),host 存的是旧 IP → id/host 双失配 → 永久离线(坑 6 的状态侧遗留)。

**路径 B|陈旧快照覆盖,把可恢复变成永久**:
- 每 2s 的 `refresh_layout_from_disk`→`merge_disk_layout_into_runtime`(lib.rs:1679)只保本机 key 与 client 配对,远端设备 key/host/ports 全部回退成磁盘旧值;而磁盘只在用户保存/显示器变化/配对时写盘(lib.rs:1606/4741/9729),常态落后于运行时。
- 前端整份保存的 `merge_runtime_owned_layout_fields`(lib.rs:1634)只保护本机 key 与 `upgrading`,远端设备 key/id/host 可被陈旧 React 快照回写落盘,把路径 A 钉死。
- `online/input_ready/upgrading_until_ms` 等瞬态字段也被持久化进 layout.json。

**路径 C|瞬时闪断**:announce 中断超 90s(睡眠/网络切换/丢包/时钟前跳)→ peer 被 prune → 离线,恢复后 ≤3s 自愈但有闪断。P1-2 收敛。

**核心思路**:路径 A 的证书漂移**不能**靠自动换证书修复(安全边界,见 §5),而是:①陈旧快照不再钉死可自愈状态(路径 B);②弱匹配恢复状态显示 + 自动弹窗给出一键修复(路径 A 的 UX 侧);③非 manual 设备 id 自动跟随对端(关闭坑 6 状态侧遗留);④强匹配防冒充语义不变。

## 4. 实施任务

### P0-1 统一「运行时归属字段」合并,杜绝陈旧快照覆盖(必做)

1. 新增 `merge_runtime_owned_device_fields(incoming: &mut LayoutState, current: &LayoutState)`(放 `merge_local_runtime_device_fields` 旁):对 `incoming.devices` 中每个 `role != "local"` 的设备,按 `id` 在 `current.devices` 找同 id 设备,找到则按下列规则合并(**current=运行时/后端,incoming=磁盘/前端快照**):
   - `transport_public_key`:current 非空 → 用 current;否则保留 incoming(**任何情况下不得把非空 key 变空**)。
   - `protocol_version`/`transport_port`/`quic_port`:current 非 0 → 用 current;否则保留 incoming。
   - `upgrading`/`upgrading_until_ms`:用 current(吸收现有 `merge_remote_upgrading_fields` lib.rs:1663,可删除该函数或内部复用)。
   - `host`:`source == "manual"` → 保留 incoming(用户显式指定,§5 不变量);否则 current 非空 → 用 current,否则保留 incoming。
   - 其余字段(name/screens/color/pointer_speed/scroll_speed/platform 等)一律 incoming 优先(用户可见可编辑)。
2. 两个调用点都接入:① `merge_runtime_owned_layout_fields`(lib.rs:1634,前端整份保存);② `merge_disk_layout_into_runtime`(lib.rs:1679,磁盘合并)。
3. 瞬态字段不落盘:在 `write_layout_to_disk`(lib.rs:4343)内部**对克隆体**做归一化(所有设备 `online=false、input_ready=false、upgrading=false、upgrading_until_ms=0`)后写盘,调用方内存值不受影响;并在 `normalize_saved_layout`(lib.rs:4897)读盘侧同样清零(旧 layout.json 已带脏值,双保险)。
4. 新增单测(命名可调整,语义必须覆盖):
   - `merge_keeps_runtime_remote_identity_over_stale_snapshot`:远端设备 key/protocol/ports/host(非 manual)不被陈旧快照回退;
   - `merge_never_clears_nonempty_runtime_key`:current key 非空时不会被 incoming 空值清掉;
   - `write_layout_normalizes_transient_presence_fields`:落盘后瞬态字段归零,读回不带陈旧状态;
   - 扩展既有 `save_merge_preserves_backend_pairing_from_stale_settings_snapshot`(lib.rs:11174 附近)覆盖远端字段;
   - 保持全绿:`manually_selected_peer_address_survives_discovery_and_file_transfer`(lib.rs:10547)。

### P0-2 弱匹配自愈 + 设备 id 自动跟随(必做)

**2a. 弱匹配(恢复状态显示,不触碰信任)**

1. **强匹配 `device_matches_peer`(lib.rs:8491)的判断语义不变**(防冒充,见 §5)。
2. 新增弱匹配(建议签名 `fn weak_device_match(device, peer, cluster_id) -> Option<WeakMatchReason>`),生效条件**全部**满足:
   - 同 cluster 且非 pairing_required(`peer.cluster_id == cluster_id` 且 cluster_id 非空、`!peer.pairing_required`);
   - 信号匹配(大小写不敏感、trim):`device.name == peer.name`,**或** `device.host` 按 '/' 拆段后任一段与 `peer.host`(对端主机名)相等;
   - **双向唯一**:在本次 presence pass 内,该设备与该 peer 均未被强匹配认领,且不存在第二个弱候选(设备侧、peer 侧都要唯一)。
3. `apply_peer_presence`(lib.rs:8428)改两遍:第一遍强匹配(现逻辑不动);第二遍对「剩余离线设备 × 未认领 peer」做弱匹配,唯一命中 → 仅置 `device.online = true`、`device.input_ready = peer.input_ready`,**不改写** `transport_public_key/host/ports`。
4. 前端对齐:`pairingRepair.ts` 新增 `weakMatchesPeer(layout, device, peer)`(与 Rust 同语义,防抢占参照 `findRepairDeviceForPeer`:132);`App.tsx` `applyPeerPresence`(:3945)加第二遍弱匹配(仅更新 online/inputReady)。

**2b. 设备 id 自动跟随(非 manual;委托方 D3 决策)**

> 目标:非 manual 设备的 `device.id` 强匹配命中后同步为 `peer_device_id(peer)`,彻底关闭「id 漂移后 id/host 双失配」;manual 设备 id 永不自动变(用户引用稳定)。**这是唯一允许改写 device.id 的路径,弱匹配永不改 id。**

1. 新增 `fn retarget_device_id(layout: &mut LayoutState, old_id: &str, new_id: &str) -> bool`,级联更新:
   - `device.id = new_id`;该设备所有 `screens[].device_id = new_id`;`screens[].id` 同步重映射(保持原有唯一性规则,可按 `unique_peer_screen_id` 重生成或前缀替换,**必须保留 x/y**,见第 3 点);
   - `layout.active_device_id == old_id` → `new_id`;(`layout.selected_screen_id` 命中该设备旧 screen id → 对应新 screen id);
   - **冲突防护**:`new_id` 已被另一设备占用 → 不改写,返回 false 并 `log::warn!`(两台设备绝不合并)。
   - 实现提示:先收集待重映射项、循环结束后统一应用,避免 `&mut` 借用冲突。
2. 触发条件(在 `apply_peer_presence` 强匹配命中处):`device.source != "manual"` 且 `peer_device_id(peer) != device.id` 时执行 retarget,之后再 `update_device_from_peer`。弱匹配(2a)不触发。
3. **屏幕摆放不得丢**:`screens_from_peer`(lib.rs:8581 附近)按 id 找 existing 取 x/y 时增加 **index 对位兜底**(peer.screens 与 existing 数量相同且按 id 未命中时,按同 index 取 x/y)——id 变更后用户摆放不回默认。
4. 前端一致:`upsertPeerDevice`(pairingRepair.ts:160)的 id 取值改为——非 manual:`peerDeviceId(peer)`(修复后与后端同规则);manual:保留 `existingDevice?.id`。颜色/名称/速度/屏幕摆放的既有保留逻辑不变。**注意**:`pairingRepair.test.ts` 中断言"修复保留 id"的用例需按新语义更新(非 manual 期望新 id、manual 期望旧 id),更新处逐一注明理由。
5. 新增单测:
   - `strong_match_retargets_device_id_and_keeps_screen_placement`:id 切换后 screens x/y 保留、active_device_id/selected_screen_id 正确重映射;
   - `manual_device_id_never_retargeted`;
   - `retarget_refuses_when_target_id_taken`(冲突时 id 不变、有 warn);
   - 保持全绿:`peer_presence_keeps_trusted_key_when_peer_id_changes`(lib.rs:10603)、`discovery_cannot_replace_paired_device_certificates`(lib.rs:10568)、`peer_presence_marks_missing_remote_offline`(lib.rs:10524)。
   - TS:`src/pairingRepair.test.ts` 补 `weakMatchesPeer` 用例(唯一性、大小写、防抢占)。

### P0-3 证书轮换「自动弹窗 + 一键修复」(必做;委托方 D4 决策)

1. 判定函数放 `pairingRepair.ts`: `findIdentityDriftPeer(layout, peers)` —— 弱匹配(或 `findLivePeerForDevice`:68)命中的设备中,`peer.transportPublicKey !== device.transportPublicKey` 或设备 key 为空的情形;不抢已认领设备。
2. 自动弹窗(⚠ **必须遵守 2026-10-安全键盘输入状态误报复盘的教训**):
   - 检测到身份漂移时弹出对话框:标题「设备证书已变化」,正文含设备名/原因/影响,动作:「一键修复」「稍后处理」;
   - **同因只弹一次**:同一 (device.id, peer 传输公钥) 漂移,用户关闭后 2s 轮询**绝不重开**;参考 `src/runtimeBlocker.ts` 的 `applyRuntimeBlockerDetail`(同因只弹一次、解除自动关闭)机制扩展一个 identity-drift 通道,或在 App.tsx 用 ref 记录已提示指纹;
   - **解除自动关**:修复成功或漂移消失(设备恢复强匹配/peer 离线)时自动收起当前弹窗;
   - 「稍后处理」= 本次漂移不再弹(设备行徽标仍显示);同一设备再次发生新漂移(指纹变化)可再弹;
   - **不堆叠**:多台同时漂移只显示第一条(或合并为一个列表弹窗),杜绝弹窗风暴。
3. 行内徽标保留:Devices 页设备行(App.tsx:2700 附近)对命中设备显示「证书已变化」徽标 +「一键修复」按钮,与弹窗共用同一修复流程。
4. 修复流程走既有 `handleRepairPeerDevice(peer, device)`(App.tsx:1971)→ `beginPairing`(实时发现地址优先)→ 用户输入 Win 端显示的验证码 → `confirmPairing` 原位更新(`upsertPeerDevice`,按 P0-2b.4 的 id 规则)。
5. i18n:文案进 `src/i18n.ts`(中英)。
6. 验收:`npm test` 全绿、`npm run build` 通过;弹窗"同因只弹一次、解除自动关"有 TS 单测(纯逻辑函数抽到可测模块)。

## 5. 安全不变量(不得破坏,评审将逐条核对)

1. **discovery 不得替换已 pin 的证书**:`discovery_cannot_replace_paired_device_certificates`(lib.rs:10568)语义保留;弱匹配**永不**改写 `transport_public_key`/`paired_controllers`;证书更新只能经既有配对码流程(一键修复=配对码流程,不是自动换证)。
2. manual 设备的 host 与 id 不被 discovery/合并覆盖:`manually_selected_peer_address_survives_discovery_and_file_transfer`(lib.rs:10547)。
3. id 漂移不换信任:`peer_presence_keeps_trusted_key_when_peer_id_changes`(lib.rs:10603)——id 自动跟随(2b)**只改 id 字符串,绝不触碰 key**。
4. 陈旧前端保存不得清掉 `cluster_id/pair_secret/paired_controllers`:`save_merge_preserves_backend_pairing_from_stale_settings_snapshot`(lib.rs:11174 附近)。
5. 坑 6 路由修复不动:`packet_targets_local` 的 `peer-{hostname}-` 前缀放行逻辑保持原样。
6. 不改 QUIC 鉴权/握手路径(quic_transport.rs)、不动 `input-helper/`、不改发现协议 wire 格式。
